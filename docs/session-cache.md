# 会话访问缓存

Web、Desktop 和 Android 的会话切换采用以下共同规则。此处约束用户行为和状态一致性，各端可以使用各自的状态管理与滚动组件。

## 进入与返回

- 首次进入或缓存被淘汰后，读取初始快照。
- 命中已完成初始加载的缓存时，立即呈现已加载的消息、历史分页、展开状态和阅读位置，不因返回页面重新读取初始快照。
- 返回后重新订阅，并从已应用事件的游标补齐变化；仅收到明确要求重建的恢复结果或事件时重读快照。用户主动刷新仍可读取快照。
- 历史分页的水位不能推进实时恢复游标。保存的内容和游标必须对应，不能跳过尚未呈现的变更。
- Android 重新订阅时独立读取计划状态；重建快照期间暂停历史分页，并丢弃重建前发出的分页结果。
- 恢复失败时保留可读的缓存，后续允许重试；服务端确认会话无权访问或已不存在时，清除该会话内容及缓存。

## 阅读与实时状态

- 向上阅读时保留阅读意图，补齐消息或刷新运行信息不能强制滚到底部；原本跟随最新消息时继续跟随。
- 恢复工具分组和消息详情的展开状态。移动端可使用消息、文字锚点及列表偏移适配原生布局。
- 缓存用于立即展示；运行状态、能力、通知和已加载目录按既有实时恢复规则刷新，不能把缓存当作永久有效的操作依据。
- 离开页面后关闭该页面订阅，不为缓存会话长期保留 WebSocket 或视图。

## 生命周期与隔离

- 缓存按服务器、账号隔离，退出登录后释放；Android 还按登录会话身份隔离。
- 每次访问有独立生命周期。迟到的快照、分页、运行信息或操作结果不能更新其他会话，也不能覆盖同一会话的下一次访问。
- 已发出的模型、权限选择写入允许完成；返回后的发送应等待同会话尚未完成的选择写入。离开页面不自动重发消息。
- 页面忙碌标记和连接状态不作为正在执行的任务恢复；缓存只保留数据与可恢复的阅读信息。

## 容量与平台范围

三端当前使用内存缓存，默认最多保留 5 个最近访问的会话，并以约 16 MiB 的字符串存储估算限制容量，超大记录不进入缓存。估算不代表进程内存总量。浏览器刷新或 Android 进程结束后不承诺恢复本次会话缓存，草稿保存仍使用原有机制。

iOS / iPadOS 继续使用现有会话仓库与落盘机制，本次不调整其进入时裁剪历史及阅读状态的行为。新增持久缓存或更改平台策略时，应另行说明恢复与失效规则。

## 验收场景

各端实现至少验证：A→B→A、保留已加载历史与阅读位置、流式输出中离开、迟到结果、凭据刷新、恢复失败、要求重建快照、账号隔离、无权访问及缓存淘汰。

- Web：会话缓存、控制器和组件切换测试位于 `web-next/test/session-*.test.mjs`。
- Android：`SessionStateCacheTest` 验证缓存和访问隔离，`SessionSelectionLifetimeTest` 验证跨访问的选择写入与发送顺序，`MessageListScrollFollowTest` 验证原生阅读与展开恢复；实时恢复沿用已有控制器测试。
- Desktop：保持 #609 的现有行为及回归测试。
