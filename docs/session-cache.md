# 会话访问缓存

Web、Desktop 和 Android 的会话切换采用以下共同规则。此处约束用户行为和状态一致性，各端可以使用各自的状态管理与滚动组件。

## 进入与返回

- 首次进入或缓存被淘汰后，读取初始快照。
- 命中已完成初始加载的缓存时，立即呈现已加载的消息、历史分页、展开状态和阅读位置，不因返回页面重新读取初始快照。
- 返回后重新订阅，并从已应用事件的游标补齐变化；收到重建要求时重读快照。Web 的增量请求临时失败时也会尝试读取快照。用户主动刷新仍可读取快照。
- 历史分页的水位不能推进实时恢复游标。保存的内容和游标必须对应，不能跳过尚未呈现的变更。
- Android 重新订阅时独立读取计划状态；重建快照期间暂停历史分页，并丢弃重建前发出的分页结果。
- 恢复失败时保留可读的缓存；Android 在所需快照成功应用前会继续重试。会话接口确认无权访问或会话已不存在时，清除该会话内容及缓存。Web 和 Android 的模型或权限目录不可用时，会话历史仍可阅读。

## 阅读与实时状态

- 向上阅读时保留阅读意图，补齐消息或刷新运行信息不能强制滚到底部；原本跟随最新消息时继续跟随。
- 恢复工具分组和消息详情的展开状态。移动端可使用消息、文字锚点及列表偏移适配原生布局。
- 缓存用于立即展示；运行状态、能力、通知和已加载目录按既有实时恢复规则刷新，不能把缓存当作永久有效的操作依据。
- 离开页面后关闭该页面订阅，不为缓存会话长期保留 WebSocket 或视图。

## 生命周期与隔离

- 缓存按服务器、账号隔离，退出登录后释放；Android 还按登录会话身份隔离。
- 每次访问有独立生命周期。迟到的快照、分页、运行信息或操作结果不能更新其他会话，也不能覆盖同一会话的下一次访问。
- 已发出的模型、权限选择写入允许完成；返回后的发送应等待同会话尚未完成的选择写入。离开页面不自动重发消息。
- 页面忙碌标记和连接状态不作为正在执行的任务恢复；缓存只保留数据与可恢复的阅读信息。

## 容量与平台范围

三端的内存缓存默认最多保留 5 个最近访问的会话，并以约 16 MiB 的字符串存储估算限制容量，超大记录不进入缓存。估算不代表进程内存总量；Android 内存中另存的原始协议条目与显示内容共用字符串，不重复计入。内存缓存在浏览器刷新或 Android 进程结束后不保留；Android 另有落盘缓存（见下节），草稿保存仍使用原有机制。

iOS / iPadOS 继续使用现有会话仓库与落盘机制，本次不调整其进入时裁剪历史及阅读状态的行为。新增持久缓存或更改平台策略时，应另行说明恢复与失效规则。

## Android 的落盘缓存（v3）

v3 的 Server 不保存会话正文，设备离线时只能看客户端自己缓存过的内容，所以 Android 在内存缓存之外再把会话写进应用的 `noBackupFilesDir`（不参与系统备份）。

- 内容：保存 Server 发来的原始协议文档，即会话信息和时间线条目，以及恢复游标、`nextSeq`、`hasMore` 和阅读位置；不保存投影后的界面状态。读取时按快照的同一条投影路径重建消息，投影代码变化不会让缓存失效。运行状态、能力、通知、目录、计划与目标和本地尚未确认的消息不落盘，下次访问重新读取。只有拿到过权威快照的会话才落盘，设备离线时得到的空快照不算。
- 写入时机：离开会话时、App 进入后台时，以及查看过程中内容或游标变化时最多每 8 秒一次。所有文件读写在同一个后台线程上按顺序执行，不在主线程。
- 读取：内存未命中时先读盘，命中后立即呈现，并从保存的游标补齐，不重读快照；游标太旧时按「要求重建快照」处理。
- 容量：每个账号最多保留 50 个最近访问的会话，总量约 64 MiB，超出时按最近访问时间淘汰。记录版本变化时旧记录直接作废，不做迁移。
- 隔离与清理：按服务器和账号（哈希后的目录名）隔离，账号未知时不落盘；退出登录或登录失效时删除该账号的落盘内容，之后才关闭或进入后台的页面也不会再写回；登录另一个账号时删除其他账号的落盘内容。会话接口确认无权访问或会话已不存在时，同时删除该会话的落盘内容。
- 设备离线（protocol 1.2）：快照、增量和向上翻页返回 `deviceOffline` 时保留已加载的内容、游标和 `hasMore`，离线期间不自动向上翻页，任何实时事件都不移动恢复游标；离线期间收到的实时时间线条目先暂存，补齐缺口后再按序号应用。有缓存时输入框上方提示「设备离线」，没有缓存时时间线显示「设备离线，上线后查看。」。设备上线或收到 `session.catchup_required` 后按自己的游标补齐，恢复进行中收到的要求在本次结束后再补一次；第一次读取就离线时，设备上线后先重读快照。

## 验收场景

各端实现至少验证：A→B→A、保留已加载历史与阅读位置、流式输出中离开、迟到结果、凭据刷新、恢复失败、要求重建快照、账号隔离、无权访问及缓存淘汰。

- Web：会话缓存、控制器和组件切换测试位于 `web-next/test/session-*.test.mjs`。
- Android：`SessionStateCacheTest` 验证缓存和访问隔离，`SessionSelectionLifetimeTest` 验证跨访问的选择写入与发送顺序，`MessageListScrollFollowTest` 验证原生阅读与展开恢复；`SessionDiskCacheTest` 验证落盘的写入、读取、版本作废、淘汰和退出登录后不写回，`SessionDeviceOfflineTest` 验证离线快照、补齐与游标；实时恢复沿用已有控制器测试。
- Desktop：保持 #609 的现有行为及回归测试。
