# Agents Anywhere 2.1.0

2.1.0 是一次接口更新（MINOR）：管理统计从"按请求重算"改为"按事件记录"，`/api/v2/admin/dashboard/*` 被 `/api/v2/admin/usage/*` 取代；DSH 插件与 Connector 之间的本机桥接，以及 Desktop / 插件管理 Connector 的本机控制通道，统一从手写的 JSON-RPC 迁移到 [MeshCall](https://github.com/t4wefan/meshcall) 0.3.0。按[版本号规则](../versioning.md)，所有端的版本号统一升到 2.1.0；本文档在安装包构建前只记录接口变化、各端最低配套版本、数据库迁移和已知限制，安装包记录待发布时补充。

## 接口变化

- 新增 `GET /api/v2/admin/usage/report?from&to&tz` 与 `GET /api/v2/admin/usage/live`，口径见 [Admin Usage API](../api/admin-usage.md)。
- 删除 `GET/PATCH /api/v2/admin/dashboard/settings`、`GET /api/v2/admin/dashboard/overview`、`POST /api/v2/admin/dashboard/snapshots/*`。2.0.x 的 Web / Desktop 看板页面连接 2.1.0 Server 时会收到 404，需要升级客户端。
- 认证依赖 `current_user_id` 现在会记录用户活跃（进程内每用户 5 分钟节流），不再通过 `/auth/me` 单独写 `platform_user_activity`。
- `session.turnEnded`、`notice.upsert`、`runtime.error` 通知在 Server 侧额外产生统计事件；工作区创建切换到版本化 MeshCall 操作契约，配套及回退要求见下文。
- Runtime 实例状态（`RuntimeInstanceStatus`、`runtime.statusChanged`、`runtime.start` 回复）新增可选 `phase {code, message, retryable?}`，描述非 error 状态内的子步骤（如 `starting` 期间的 `syncing`）。Server 在实例报告 starting phase 时不再重发 `runtime.start`，会话操作得到可重试的 `409 runtime_starting`。老 Connector 不发 `phase`，行为不变。
- Codex Runtime 配置新增 `ipcEnabled`、`ipcDeeplinkHandoff` 两个布尔项（默认开），schema revision 升到 8；旧配置缺省按开处理。
- Runtime 实例限制分层：Server 按已配置数限制创建（超限 409），Connector 只限制同时运行数；同一类型不再支持保存多份配置。删除 Runtime 后不再保留未配置的占位行，迁移 `v2_44` 清理历史占位行。
- Server 移除 v1 数据导入工具（`python -m agent_server.infra.db.migrations rehearse-v1`），仍在 v1 的部署须先用 2.0.x 完成导入。`AGENT_SERVER_DB_BACKEND` 不再被读取，可以从部署配置中删除。Server 测试需要 `AGENT_SERVER_TEST_DB_URL` 指向一次性 PostgreSQL 数据库，见[开发指南](../development.md)。
- **本机控制通道**：`anywhere-cli rpc` 不再使用 stdio JSON-RPC。进程启动时拉起本进程专属的 MeshCall `LocalRouter`（macOS/Linux 为 `~/.agents-anywhere/router/<instanceId>.sock`，Windows 为命名管道 `agents-anywhere-<instanceId>`），注册 `aa.local.v2.Control` 与 `aa.local.v2.Logs`，并在 stdout 写一行就绪信息后不再输出：

  ```json
  {"kind":"connector.ready","version":1,"instanceId":"…","pid":12345,"endpoint":{"unixPath":"…"},"key":"mk_host_…"}
  ```

  宿主用该 endpoint 与 key 建立 `Mesh` 后调用 `getState`、`getPaths`、`acquireOwnership`、`getConfig`、`saveConfig`、`start`、`stop`、`restart`、`startPairing`、`cancelPairing`；状态与配对通过 `Control.events(since)` 订阅；运行日志由 `Logs.write/read/tail/clear` 持久化与读取（见[日志契约](../../contracts/dsh-bridge/2.0/logs.md)）。客户端保存 `lastSeq` 并在断线后重订。方法语义与旧 JSON-RPC 一一对应，契约见 [本机记录 2.0](../../contracts/local-machine/2.0/README.md)。
- **所有权冲突**改为 MeshCall 应用错误码 `connector_already_running`（`details` 仍含 `reason` 与 `owner`）；其他意外失败为 `connector_error`，参数错误为 `invalid_argument`。控制通道在冲突后继续可用。
- **DSH 桥接契约 2.0**（[contracts/dsh-bridge/2.0](../../contracts/dsh-bridge/2.0/README.md)）：Connector 发布 rendezvous `~/.agents-anywhere/dsh-bridge/connector.json`；插件连接 Connector 的 Router 并注册 `aa.dsh.v2.Bridge`，Connector 注册 `aa.dsh.v2.Sync`。事件批从「通知 + 停等 ACK」改为 `Sync.ingestBatch` 调用，返回即已 ingest；检查点改为 unary `loadCheckpoint` / `saveCheckpoint` / `deleteCheckpoint`；快照改为 `Sync.ingestSnapshot` 客户端流。`runtime.sync.progress`、ACK 超时与 `batchSeq` 重校准删除。
- **硬切 2.0**：插件不再写 1.0 的 `<DSH_HOME>/agents-anywhere/bridge/endpoint.json` 镜像；2.0.x 的 Connector 找不到 Bridge，只会停在“等待 DSH”。本机的插件、Connector 与 Desktop 必须一起升级到 2.1.0。
- 本机运行日志由 Connector 统一持久化：`~/.agents-anywhere/logs/` 下按段轮转的 JSONL（默认最多 10000 条 / 32 MiB / 7 天），Connector 与 DSH Bridge 写入同一日志服务（`source` 分为 `plugin` / `bridge` / `connector`）；Desktop 与插件不再各自保存运行日志副本，日志页与导出在 Connector 可用时读取中央存储，不可用时回退到各自的启动/引导诊断。stdout 不再承载 RPC 流量。
- 依赖：Connector `meshcall==0.3.0`（PyPI 平台 wheel 自带 Router 二进制）；插件与 Desktop `meshcall@0.3.0`（npm 按平台可选依赖自带 Router 二进制）。

## 产品变化

- Web 认证页补齐原生表单与字段名称；登录和找回密码的邮箱标记为 `autocomplete="username"`，改善密码管理器对账号与密码的配对识别。Enter 与主按钮统一走表单提交，密码显示、验证码和 OAuth 等辅助按钮不触发表单提交。此修正不代表已确认所有线上登录失败的根因。

- 管理看板重做：按请求所在时区切天，提供 7 / 30 / 90 天预设和自定义范围；新增 WAU / MAU 滚动窗口、新用户留存、按小时分布、按 Runtime 的使用明细、设备与 Runtime 安装情况、回合结果与时长分位、审批等待时长、Runtime 错误、会话读取次数与只读会话（打开过但没有发过消息）等指标，以及"在线设备 / 运行中回合 / 15 分钟内活跃"的实时条。
- Runtime 维度不再写死 Codex / Claude Code / DSH，而是按会话绑定的 Runtime 类型动态统计，显示名来自设备上报的发现结果。
- 统计数据从升级日起按事件累计，不回填历史。
- Web / Desktop 管理页与个人设置页改为和主页一样的侧栏布局：账号菜单只保留一个「管理」入口；管理侧栏分「数据」（看板的概览、用户、使用量、设备与 Runtime、运行质量）、「管理」（团队、公告）和「服务」（常规、身份认证、邮件、服务信息）三组，公告和服务配置各自独立成页；看板的数字改为一行同面板的指标条，页面宽度与其他管理页一致；设置页的分类移到侧栏，侧栏顶部可返回主页；侧栏在主页与管理 / 设置之间切换时并排左右滑动（进入时整体向左滑、返回时向右滑回，两个侧栏不重叠）。路径改为 `#/admin/<section>`，旧的 `#/dashboard`、`#/team`、`#/service` 仍然打开对应页面。管理页和设置页（已归档会话除外）不再加载工作区清单和看板推送，返回主页时恢复。
- Codex：Connector 接入 Codex 桌面 App / IDE 插件的 IPC 路由，在 Codex 窗口里打开的线程会被跟随并通过该窗口代为操作（发消息、steer、中断、审批、模型与权限切换、附件），Connector 自己持有的线程也能被 Codex 窗口跟随。新增会话命令 `/open-in-codex-app`（让桌面 App 打开当前线程）与 `/kill-chatgpt`（停掉桌面 App 以释放其写锁）。两项能力可在 Codex Runtime 配置里关闭。细节见 [Codex IPC 接管](../codex-ipc-takeover.md)。
- Claude：模型标题按 `resolvedModel` 推导为“Opus 5.5 / Sonnet 5 (1M context) / Default (…)”等可读形式，覆盖 Bedrock、Vertex、日期后缀与旧式模型 ID（#289）；无 AI 标题或自定义标题的会话将首条消息折叠空白后截断到 48 字（带 `...`），不再把整段首条消息塞进会话名（#219）。
- DSH：同步会话期间 Runtime 显示为"启动中 · 正在同步 DSH 会话…"，不再显示为异常；同步期间发起的会话操作不再打断同步。
- DSH：历史或实时内容里出现孤立的 UTF-16 代理字符（被截断的 emoji、工具输出里的乱码）不再让整个 runtime 卡在「正在同步」：插件在计算内容哈希前把它们替换为 `�`（原 #222，TNTest）；Connector 对旧版插件发来的原始字符按 `JSON.stringify` 的转义方式计算哈希、校验通过后再把发往 Server 的文本规范化，发送侧的 UTF-8 编码也不再因此失败。
- DSH：某个会话的历史被 Server 拒绝（超过请求体上限的 413、其他 4xx，或响应里被标记为 rejected）时只隔离这个会话：runtime 照常进入「运行中」，其他会话正常同步；该会话显示为不可用（原因 `history_too_large` / `history_rejected`），不写检查点，之后按退避（30 秒起，超大历史 5 分钟起，最长 30 分钟）请求插件重新捕获，被接受后恢复可用。以前一个大会话会让整台设备的 DSH 永久停在「启动中」（#278 的症状；设计取自 #291）。
- DSH：同步任务不再因为一次状态上报失败而悄悄死掉。Connector 向 Server 上报「正在同步 / 同步中断 / 运行中」失败时（例如 Server 连接恰好断开）只记日志，继续重订阅；连续失败按 1 s、2 s、4 s … 最长 30 s 退避；同步任务若因意外异常退出，运行时在 2 s 后重建它，而不是停在「启动中」直到重启 Connector（#293）。
- DSH 插件：本机管理锁改为「随机端口 + 记录 + 连接核实」：持有者监听系统分配的回环端口并把 `{port, pid, token}` 写进数据目录，竞争者连上去核对 token。不再依赖固定端口段，Windows 上被 Hyper-V / 系统保留端口拒绝导致的「本机连接启动失败：访问权限不足」不会再出现（#144 / #164）。旧版插件与新版短暂并存时互斥不生效，升级后请只保留一个实例。
- Desktop / Connector：本机机器记录（`contracts/local-machine/2.0`）的事务锁改为「随机端口 + 记录 + 连接核实」，与 DSH 插件的管理锁同一机制；Windows 保留端口段不再影响 Connector 的启动检查（#217）。旧版与新版写入者并存时互斥不生效，各入口请一起升级。
- DSH：超过 8 MiB 的完整快照分页上传——第一页整体替换、后续页追加，Server 不需要改动，代理的请求体上限只需 ≥ 8 MiB；单会话历史过大（#278）不再被 413 拒绝。分页之间 Server 上该会话短暂只有前半段，Connector 以连续发送、只重试当前页来缩短这个窗口。细节见[快照上传](../dsh-snapshot-uploads.md)。
- DSH：大历史的快照上传不再受固定 60 秒 ACK 窗口限制——慢速上传只是更慢的 `ingestBatch` / `ingestSnapshot` 返回，连接由 MeshCall keepalive 维持；Connector 把快照编码到临时文件后流式发送，提交阶段的内存不再随历史大小增长（原 #257 / #259，Iroli007）。HTTP 仍一次提交完整快照，不提供云端断点续传，见 #323。
- Connector 查询与订阅可并发：慢的配对或配置请求不会阻塞 `getState` 等后续请求。启动、停止、重启与配置保存共用生命周期锁，避免并发重启留下额外后端；配对取消覆盖地址解析阶段，旧配对不能在取消后继续保存凭据或自动启动。
- 控制变更不自动重试；生命周期变更或后端清理尚未完成时，新的启停、重启与配置保存立即返回 `connector_busy`（不可自动重试），避免排队后执行过时操作或重复重启。
- Connector 状态与日志可续订：Desktop 与插件在连接中断后从最后一个序号继续；运行日志序号跨 Connector 重启与清空保持递增，落后于保留窗口时首条记录标记 `gapBefore`，不需要重启 Connector。插件日志视图统一支持查看插件、Bridge 与 Connector 三类日志。
- 运行日志不再阻止 Connector 启动：损坏的日志段会截断到最后一条完整记录，日志目录不可用时降级为内存日志；独立 CLI 启动时日志 Router 也是 best-effort（DSH 仍需要 Router），Codex/Claude 会话不受影响。
- 本机 Router 由 Connector 监督：意外退出后自动重启，endpoint 与 key 不变，插件与 Desktop 自动重连。
- DSH 同步关闭时先停止接收新数据，同时取消订阅、正在上传的数据与重捕任务，再等待清理，避免订阅退出等待仍被上传占用的锁。

## 原生状态驱动的项目同步

- DSH、Codex、Claude Code 当前原生状态决定项目和会话归属；目录观察在工作设备完成。
- 同名、同目录、不同 Runtime 实例项目独立；移除 AA 原生项目改名及目录修改入口，保留置顶和用户归档。
- 项目/目录默认 30 秒、完整成员默认 5 分钟独立核对，事件与手动刷新进入统一队列；正文历史同步独立。
- AA 创建项目绑定 Runtime 与幂等请求 ID；原生成功回读后展示，超时保留未知状态。Claude 通过首次对话形成目录项目。
- 四端展示来源、核对时间和未分组原因；有效原生空项目可见。
- 产品版本沿用 2.1.0，相关组件须使用配套构建；升级与回退见[升级指南](../upgrading.md)和[同步契约](../api/project-archiving.md)。

本说明描述实现；源码检查、运行验证及未验收边界见 [MeshCall 创建链路记录](../runtime-protocol/meshcall-server-connector-plan.md)。

## 项目同步评审修复

- 清除 Runtime 实例时同时退役该来源的项目和同步快照，迟到上传不能恢复已退役来源。
- 区分来源状态和逐根目录状态；多根项目可在已确认正常的目录中创建会话，异常根目录不会误拦截其他目录。
- 工作区同步采用独立来源锁，设备生命周期锁仅用于短时准入；历史上传及其他来源的 HTTP 上报不再等待整轮工作区应用。
- Codex 项目能力按实际实例协议公布，区分不支持与暂时故障。不支持的实例停止周期重试，并提示升级项目协议。
- 创建操作可跨页面和应用重启恢复。各端提供继续核对及明确再次新建，成功结果在客户端确认收到之前仍保留恢复入口。

- 创建与 Runtime 启动完成后的目录刷新提示失败，不再把已完成操作返回为失败。
- Codex 版本探测在 POSIX 系统上超时会同时清理启动器的子进程，避免异常启动器耗尽进程资源。

## Server ↔ Connector MeshCall 工作区创建

本次补充 Server ↔ Connector MeshCall 工作区创建链路，产品版本沿用 2.1.0。Server、Connector、
DSH 插件及客户端须使用包含本次契约的配套构建；协议不匹配时提示升级。尚未发布安装包。

- Server 启动入口统一为 `python -m agent_server.main`，父进程自动管理回环 Router；
  所有 API worker 共用。Docker 不需要额外部署 Router 服务，也不需要额外公网端口。
- bootstrap 与 WebSocket 入口见 runtime-operations/1.0 契约；只给已认证、有效连接
  的 Connector 签发 15 分钟注册凭据，按设备和连接代次隔离并定向调用。
- 创建请求事务保存后返回操作 ID，后台执行；网络断开、页面关闭不撤销已接受操作。
- 重复请求复用回执，参数冲突拒绝；结果不明保留 unknown，原生成功与项目同步分开。
- DSH 原生工作区操作增加本地持久回执；发生“原生可能已完成、结果未落盘”时不盲目重做。
- 旧 `project.create` RPC 不再执行新创建，明确要求升级；现有其他通信通道保持原协议。
- 数据库迁移 v2_46 保留旧操作记录与未知结果。回退必须先停止派发并保留回执，
  不可将未核对操作交给旧执行器重做。

限制：首期一个 Server 部署、多 worker，不提供 Router 集群。没有可靠原生核对能力的
操作可能保持 unknown；不承诺所有 Runtime exactly once。真实设备与原生 Runtime
验收范围见开发计划中的验收记录。

## Server 与数据库

2.1.0 的数据库 revision 为 `v2_46`（schema version `2.46`）。`v2_42` 新建 `usage_events`、`usage_inventory_snapshots`，并删除 `dashboard_daily_metrics`、`dashboard_user_daily_facts`、`dashboard_settings`、`platform_user_activity`，旧看板数据不会保留；`v2_43` 给 `device_runtimes` 增加 `phase_json` 列；`v2_44` 删除历史删除留下的未配置占位行；`v2_45` 保存原生项目、成员清单及创建回执；`v2_46` 扩展操作状态、调度租约和恢复身份。升级步骤见[升级指南](../upgrading.md)。

新增环境变量（均可省略）：

| `AGENT_SERVER_USAGE_FLUSH_INTERVAL_SECONDS` | `1` | 事件批量落库的间隔 |

## 已知限制

- MeshCall 0.3.0 为本仓库依赖的精确版本；升级需要单独评估（0.2 → 0.3 为破坏性更新）。
- Windows 命名管道路径与 Router 子进程（`--shutdown-on-stdin-close`、未签名二进制被安全软件拦截）需要在真机验证。
- 本地 PyPI 镜像（阿里云）同步 0.3.0 前，Connector 依赖显式从 PyPI 拉取 `meshcall`。
