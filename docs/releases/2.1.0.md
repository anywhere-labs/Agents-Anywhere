# Agents Anywhere 2.1.0

2.1.0 是一次接口更新（MINOR）：管理统计从"按请求重算"改为"按事件记录"，`/api/v2/admin/dashboard/*` 被 `/api/v2/admin/usage/*` 取代；DSH 插件与 Connector 之间的本机桥接，以及 Desktop / 插件管理 Connector 的本机控制通道，统一从手写的 JSON-RPC 迁移到 [MeshCall](https://github.com/t4wefan/meshcall) 0.3.0。此外新增移动端登录续期端点和模型目录的供应商分组，并明确会话创建失败与 Runtime 选择状态的语义。按[版本号规则](../versioning.md)，所有端的版本号统一升到 2.1.0；面向用户的变化摘要见 [CHANGELOG](../../CHANGELOG.md)，本文档记录接口变化、各端最低配套版本、数据库迁移、已知限制和安装包。

## 接口变化

- 新增 `GET /api/v2/admin/usage/report?from&to&tz` 与 `GET /api/v2/admin/usage/live`，口径见 [Admin Usage API](../api/admin-usage.md)。
- 删除 `GET/PATCH /api/v2/admin/dashboard/settings`、`GET /api/v2/admin/dashboard/overview`、`POST /api/v2/admin/dashboard/snapshots/*`。2.0.x 的 Web / Desktop 看板页面连接 2.1.0 Server 时会收到 404，需要升级客户端。
- 认证依赖 `current_user_id` 现在会记录用户活跃（进程内每用户 5 分钟节流），不再通过 `/auth/me` 单独写 `platform_user_activity`。
- Connector 与 Server 协议没有破坏性变化；`session.turnEnded`、`notice.upsert`、`runtime.error` 通知在 Server 侧额外产生统计事件。
- Runtime 实例状态（`RuntimeInstanceStatus`、`runtime.statusChanged`、`runtime.start` 回复）新增可选 `phase {code, message, retryable?}`，描述非 error 状态内的子步骤（如 `starting` 期间的 `syncing`）。Server 在实例报告 starting phase 时不再重发 `runtime.start`，会话操作得到可重试的 `409 runtime_starting`。老 Connector 不发 `phase`，行为不变。
- Codex Runtime 配置新增 `ipcEnabled`、`ipcDeeplinkHandoff` 两个布尔项（默认开），schema revision 升到 8；旧配置缺省按开处理。
- Runtime 实例限制分层：Server 按已配置数限制创建（超限 409），Connector 只限制同时运行数；同一类型不再支持保存多份配置。删除 Runtime 后不再保留未配置的占位行，迁移 `v2_44` 清理历史占位行。
- Server 移除 v1 数据导入工具（`python -m agent_server.infra.db.migrations rehearse-v1`），仍在 v1 的部署须先用 2.0.x 完成导入。`AGENT_SERVER_DB_BACKEND` 不再被读取，可以从部署配置中删除。Server 测试需要 `AGENT_SERVER_TEST_DB_URL` 指向一次性 PostgreSQL 数据库，见[开发指南](../development.md)。
- **本机控制通道**：`anywhere-cli rpc` 不再使用 stdio JSON-RPC。进程启动时拉起本进程专属的 MeshCall `LocalRouter`（macOS/Linux 为 `~/.agents-anywhere/router/<instanceId>.sock`，Windows 为命名管道 `agents-anywhere-<instanceId>`），注册 `aa.local.v2.Control` 与 `aa.local.v2.Logs`，并在 stdout 写一行就绪信息后不再输出：

  ```json
  {"kind":"connector.ready","version":1,"instanceId":"…","pid":12345,"endpoint":{"unixPath":"…"},"key":"mk_host_…"}
  ```

  宿主用该 endpoint 与 key 建立 `Mesh` 后调用 `getState`、`getPaths`、`acquireOwnership`、`getConfig`、`saveConfig`、`start`、`stop`、`restart`、`startPairing`、`cancelPairing`；状态与配对通过 `Control.events(since)` 订阅；运行日志由 `Logs.write/read/tail/clear` 持久化与读取（见[日志契约](../../contracts/dsh-bridge/2.0/logs.md)）。客户端保存 `lastSeq` 并在断线后重订。方法语义与旧 JSON-RPC 一一对应，契约见 [本机记录 2.0](../../contracts/local-machine/2.0/README.md)。
- **所有权冲突**改为 MeshCall 应用错误码 `connector_already_running`（`details` 仍含 `reason` 与 `owner`）；其他意外失败为 `connector_error`，参数错误为 `invalid_argument`。控制通道在冲突后继续可用。
- **DSH 桥接契约 2.0**（[contracts/dsh-bridge/2.0](../../contracts/dsh-bridge/2.0/README.md)）：Connector 发布 rendezvous `~/.agents-anywhere/dsh-bridge/connector.json`；插件连接 Connector 的 Router 并注册 `aa.dsh.v2.Bridge`，Connector 注册 `aa.dsh.v2.Sync`。事件批从「通知 + 停等 ACK」改为 `Sync.ingestBatch` 调用，返回即已 ingest；检查点改为 unary `loadCheckpoint` / `saveCheckpoint` / `deleteCheckpoint`；快照改为 `Sync.ingestSnapshot` 客户端流。`runtime.sync.progress`、ACK 超时与 `batchSeq` 重校准删除。
- **硬切 2.0**：插件不再写 1.0 的 `<DSH_HOME>/agents-anywhere/bridge/endpoint.json` 镜像；2.0.x 的 Connector 找不到 Bridge，只会停在“等待 DSH”。本机的插件、Connector 与 Desktop 必须一起升级到 2.1.0。
- 本机运行日志由 Connector 统一持久化：`~/.agents-anywhere/logs/` 下按段轮转的 JSONL（默认最多 10000 条 / 32 MiB / 7 天），Connector 与 DSH Bridge 写入同一日志服务（`source` 分为 `plugin` / `bridge` / `connector`）；Desktop 与插件不再各自保存运行日志副本，日志页与导出在 Connector 可用时读取中央存储，不可用时回退到各自的启动/引导诊断。stdout 不再承载 RPC 流量。
- 依赖：Connector `meshcall==0.3.0`（PyPI 平台 wheel 自带 Router 二进制）；插件与 Desktop `meshcall@0.3.0`（npm 按平台可选依赖自带 Router 二进制）。
- **移动端登录续期**（#260）：新增 `POST /api/v2/auth/mobile-login/refresh`，用二维码登录签发的 30 天移动端 refresh token 换取新的 `AuthResponse`。Server 校验 token 的类型、有效期、audience 和用户，拒绝缺失或已禁用的用户；续期不会延长 refresh token 原有的有效期。旧客户端不调用这个端点，行为不变。
- **模型目录供应商分组**（#411）：模型目录条目新增可选 `group: {id, displayName, itemDisplayName?} | null`，`contracts/protocol/1.0` 新增 `model-catalog`、`model-catalog-response` schema。DSH 的 `group` 由 Connector 根据插件 `listModels` metadata 中的 `provider`、`providerName`、`modelName` 生成，插件不需要更新；Codex 和 Claude 发送 `null`。客户端只在目录里有两个及以上分组时按供应商分节；`displayName` 仍保持唯一，忽略 `group` 的旧客户端照常显示平铺列表。规则见 [capabilities](../api/capabilities.md)。
- **会话创建失败**（#368）：`create-and-start` 只有在 Runtime 实际接收消息后才返回成功。Runtime 返回 `ok:false`、`accepted:false` 或 `messageAccepted:false` 时，Server 返回 HTTP 409，`detail` 包含 `code`、`message`、`sessionId`、`platformSessionCreated`、`created`、`messageAccepted`、`resultUnknown` 和 `retryable:false`。只有 Runtime 明确报告 `created:false` 且 `messageAccepted:false` 时，Server 才撤销本次空的平台记录；其他情况保留记录并返回 `resultUnknown:true`，客户端应按 `sessionId` 查询，不要直接重新创建。业务拒绝不计入成功创建或消息发送。细节见 [API 说明](../api/README.md)。
- **Runtime 选择状态**（#438）：`SessionRuntimeState.selections` 是 Runtime 确认的快照，不是保存的用户偏好。缺失的 scope 表示未知，客户端应显示「未同步」，不能回退到目录默认值；值为 `null` 表示 Runtime 使用自己的默认值。设置被接受后，下一轮才生效的 scope 列在 `metadata.pendingSelectionScopes` 中。在已有会话中发送消息时，客户端不再根据输入框的显示值附带 selection 更新。Server 只短期缓存这些状态，不写入数据库。
- **Codex 异步问答**（#439）：`interaction.respond` 也用于回答以 `input_request` Notice 呈现的 Codex 异步问题（`request_user_input_async`）。客户端沿用现有的 Notice / Form 协议，没有新增端点。
- **DSH 桥接补充**：`listAgentPresets` 的 `configField.default` 改为 DSH 自己的默认模式（`agentPresets.defaultId`），Connector 在新建会话缺少 `agentPreset` 时读取它（#410）；插件管理网关新增 `agentsAnywhereOnboarding.readStartupDiagnostics()`，返回插件初始化与 Bridge 启动失败的脱敏故障快照，见[日志契约](../../contracts/dsh-bridge/2.0/logs.md)（#369）。

## 产品变化

- Web 认证页补齐原生表单与字段名称；登录和找回密码的邮箱标记为 `autocomplete="username"`，改善密码管理器对账号与密码的配对识别。Enter 与主按钮统一走表单提交，密码显示、验证码和 OAuth 等辅助按钮不触发表单提交。此修正不代表已确认所有线上登录失败的根因。

- 管理看板重做：按请求所在时区切天，提供 7 / 30 / 90 天预设和自定义范围；新增 WAU / MAU 滚动窗口、新用户留存、按小时分布、按 Runtime 的使用明细、设备与 Runtime 安装情况、回合结果与时长分位、审批等待时长、Runtime 错误、会话读取次数与只读会话（打开过但没有发过消息）等指标，以及"在线设备 / 运行中回合 / 15 分钟内活跃"的实时条。
- Runtime 维度不再写死 Codex / Claude Code / DSH，而是按会话绑定的 Runtime 类型动态统计，显示名来自设备上报的发现结果。
- 统计数据从升级日起按事件累计，不回填历史。
- Web / Desktop 管理页与个人设置页改为和主页一样的侧栏布局：账号菜单只保留一个「管理」入口；管理侧栏分「数据」（看板的概览、用户、使用量、设备与 Runtime、运行质量）、「管理」（团队、公告）和「服务」（常规、身份认证、邮件、服务信息）三组，公告和服务配置各自独立成页；看板的数字改为一行同面板的指标条，页面宽度与其他管理页一致；设置页的分类移到侧栏，侧栏顶部可返回主页；侧栏在主页与管理 / 设置之间切换时并排左右滑动（进入时整体向左滑、返回时向右滑回，两个侧栏不重叠）。路径改为 `#/admin/<section>`，旧的 `#/dashboard`、`#/team`、`#/service` 仍然打开对应页面。管理页和设置页（已归档会话除外）不再加载工作区清单和看板推送，返回主页时恢复。
- Codex：Connector 接入 Codex 桌面 App / IDE 插件的 IPC 路由，在 Codex 窗口里打开的线程会被跟随并通过该窗口代为操作（发消息、steer、中断、审批、模型与权限切换、附件），Connector 自己持有的线程也能被 Codex 窗口跟随。新增会话命令 `/open-in-codex-app`（让桌面 App 打开当前线程）与 `/kill-chatgpt`（停掉桌面 App 以释放其写锁）。两项能力可在 Codex Runtime 配置里关闭。细节见 [Codex IPC 接管](../codex-ipc-takeover.md)。
- Claude：模型标题按 `resolvedModel` 推导为“Opus 5.5 / Sonnet 5 (1M context) / Default (…)”等可读形式，覆盖 Bedrock、Vertex、日期后缀与旧式模型 ID（#289）；无 AI 标题或自定义标题的会话将首条消息折叠空白后截断到 48 字（带 `...`），不再把整段首条消息塞进会话名（#219）。
- DSH：同步会话期间 Runtime 显示为"启动中 · 正在同步 DSH 会话…"，不再显示为异常；同步期间发起的会话操作不再打断同步。
- DSH：历史或实时内容里出现孤立的 UTF-16 代理字符（被截断的 emoji、工具输出里的乱码）不再让整个 runtime 卡在「正在同步」：插件在计算内容哈希前把它们替换为 `�`（原 #222，TNTest）；Connector 对旧版插件发来的原始字符按 `JSON.stringify` 的转义方式计算哈希、校验通过后再把发往 Server 的文本规范化，发送侧的 UTF-8 编码也不再因此失败。
- DSH：某个会话的历史被 Server 拒绝（超过请求体上限的 413、其他 4xx，或响应里被标记为 rejected）时只隔离这个会话：runtime 照常进入「运行中」，其他会话正常同步；该会话显示为不可用（原因 `history_too_large` / `history_rejected`），不写检查点，之后按退避（30 秒起，超大历史 5 分钟起，最长 30 分钟）请求插件重新捕获，被接受后恢复可用。以前一个大会话会让整台设备的 DSH 永久停在「启动中」（#278 的症状；设计取自 #291）。
- DSH：同步任务不再因为一次状态上报失败而悄悄死掉。Connector 向 Server 上报「正在同步 / 同步中断 / 运行中」失败时（例如 Server 连接恰好断开）只记日志，继续重订阅；连续失败按 1 s、2 s、4 s … 最长 30 s 退避；同步任务若因意外异常退出，运行时在 2 s 后重建它，而不是停在「启动中」直到重启 Connector（#293）。
- DSH 插件：本机管理锁改为「随机端口 + 记录 + 连接核实」：持有者监听系统分配的回环端口并把 `{port, pid, token}` 写进数据目录，竞争者连上去核对 token。不再依赖固定端口段，Windows 上被 Hyper-V / 系统保留端口拒绝导致的「本机连接启动失败：访问权限不足」不会再出现（#144 / #164）。旧版插件与新版短暂并存时互斥不生效，升级后请只保留一个实例。
- Desktop / Connector：本机机器记录（`contracts/local-machine/2.0`）的事务锁改为「随机端口 + 记录 + 连接核实」，与 DSH 插件的管理锁同一机制；Windows 保留端口段不再影响 Connector 的启动检查（#217）。旧版与新版写入者并存时互斥不生效，各入口请一起升级。
- DSH：超过 8 MiB 的完整快照分页上传——第一页整体替换、后续页追加，Server 不需要改动，代理的请求体上限只需 ≥ 8 MiB；单会话历史过大（#278）不再被 413 拒绝。分页之间 Server 上该会话短暂只有前半段，Connector 以连续发送、只重试当前页来缩短这个窗口。细节见[快照上传](../dsh-snapshot-uploads.md)。
- DSH：大历史的快照上传不再受固定 60 秒 ACK 窗口限制——慢速上传只是更慢的 `ingestBatch` / `ingestSnapshot` 返回，连接由 MeshCall keepalive 维持；Connector 把快照编码到临时文件后流式发送，提交阶段的内存不再随历史大小增长（原 #257 / #259，Iroli007）。HTTP 仍一次提交完整快照，不提供云端断点续传，见 #323。
- Connector 查询与订阅可并发：慢的配对或配置请求不会阻塞 `getState` 等后续请求。启动、停止、重启与配置保存共用生命周期锁，避免并发重启留下额外后端；配对取消覆盖地址解析阶段，旧配对不能在取消后继续保存凭据或自动启动。
- 控制变更不自动重试；生命周期变更或后端清理尚未完成时，新的启停、重启与配置保存立即返回 `connector_busy`（不可自动重试），避免排队后执行过时操作或重复重启。
- Connector 状态与日志可续订：Desktop 与插件在连接中断后从最后一个序号继续；运行日志序号跨 Connector 重启与清空保持递增，落后于保留窗口时首条记录标记 `gapBefore`，不需要重启 Connector。插件日志视图统一支持查看插件、Bridge 与 Connector 三类日志。
- 运行日志不再阻止 Connector 启动：损坏的日志段会截断到最后一条完整记录，日志目录不可用时降级为内存日志；独立 CLI 启动时日志 Router 也是 best-effort（DSH 仍需要 Router），Codex/Claude 会话不受影响。
- 本机 Router 由 Connector 监督：意外退出后自动重启，endpoint 与 key 不变，插件与 Desktop 自动重连。
- DSH 同步关闭时先停止接收新数据，同时取消订阅、正在上传的数据与重捕任务，再等待清理，避免订阅退出等待仍被上传占用的锁。
- Codex IPC 接管支持 Windows（命名管道 `\\.\pipe\codex-ipc`、`msvcrt.locking` 写锁判定、按包名识别 App 进程）。AA 新建的会话立刻出现在 Codex App 侧边栏，只是 resume 的旧线程不会重新显示。同时修复了真机验收中发现的问题：App 向 AA 持有的会话发送的消息被吞、Connector 重启后发消息报 502、`thread-follower-start-turn-timeout` 被误标为错误、App 新建的会话要重启 Connector 才能跟随，以及修改权限后被旧值覆盖（#334）。
- Codex 写入按当前 IPC 持有者路由：Connector 自己持有线程时跳过 discovery；外部持有者不可达时返回 `codex_ipc_owner_unreachable`，不再退回自家 app-server 撞写锁；IPC 重连后重新扫描已跟随的线程（#437）。
- Codex 会话的模型或权限暂时读不到时显示「未同步」，普通发送不会再把界面上的回退值写回 Runtime；Connector 重启后从 `thread/resume` 恢复设置（含 `collaborationMode` 的 reasoning effort）（#438）。
- Codex 异步问答（`request_user_input_async`）显示为可作答的表单，答案作为原生 question-reply 消息发回：原 turn 仍在运行时 steer，已结束时开始新 turn。表单可以从原生历史恢复，重复或并发提交只投递一次，Connector 重启后仍保持已回答状态（#439）。
- Codex：AA 只读取会话状态、快照或做后台同步时不再接管线程。这些操作只调用 `thread/read`，不再调用 `thread/resume`，Codex Desktop 不会再提示「已在另一个应用中打开」，可以和 AA 在同一个会话里同时对话。`thread/read` 不返回审批和沙箱设置，权限改为从 rollout 文件末尾最新的 `turn_context` 或 `thread_settings_applied` 记录读取，读不到时显示「未同步」。只有本代 app-server 进程 `thread/start` 或 `thread/resume` 过的线程才算 Connector 持有，读取时缓存的状态不再让写入误走本地（#445，修复 #438 引入的回归）。
- Codex：Connector 当 IPC 路由时，为每个请求单独查找处理方，读循环不再等待 discovery。以前两个 client 同时等对方回答会一起卡到 10 秒超时，可能把 Desktop 持有的线程误判为 `no-client-found` 并拦截 AA 的写入。写入被拦截时，日志会记录 `ipc_router=self|external|none` 和原因（#446）。
- Codex：AA 或 Codex Desktop 修改 Connector 持有会话的模型和权限时立即调用 `thread/settings/update`，不再等下一条消息；没有进程打开的会话仍在下一轮生效，不为改设置抢写锁。权限一律按配置名（`:read-only` / `:workspace` / `:danger-full-access`）传递，不再用会清空 `activePermissionProfile` 的旧 sandbox 字段，Desktop 不再把完全访问显示成「请求批准」。已知限制：Codex Desktop 记住的本机权限偏好会覆盖输入框显示，并在 Desktop 发消息时写回会话（#453）。
- Codex：恢复写入前的 deeplink 交接。会话被 Codex 桌面 App 占着、但 3 秒内没有窗口应答时，如果 App 正在运行，Connector 先用 `codex://threads/<id>` 让 App 打开这个会话，最多再等 5 秒找到 App 并收到第一份快照，然后经 IPC 交给 App 执行；交接不成仍返回 `codex_ipc_owner_unreachable`，不退回自家 app-server。配置项「把被锁定的线程交给 Codex App」（`ipcDeeplinkHandoff`）重新控制这一步；`/open-in-codex-app` 同样等到第一份快照再返回 `attached`（#455，修复 #437 引入的回归）。
- Codex：新一轮开始时就关闭上一轮的失败卡片，不再等到这一轮结束（#351）；实时与历史 Timeline 使用同一身份，搜索等条目不再重复（#433）。
- Codex / Claude Code：附件下载失败时，会话里会出现一条 warning，列出没送到的文件名并提示重发，正文和其他附件照常发送；重新发送成功后提醒转为已解决（#270）。
- DSH：Runtime 配置没有保存默认模式时（例如在 DSH 离线时保存），新建会话不再报错，改为跟随 DSH 自己的默认模式（#410）。
- DSH：插件扫描历史会话后释放原生日志、配置派生结果和同步投影缓存，内存不再随会话数增长；被淘汰的会话再收到事件时从 Connector 检查点恢复，只发送增量（#431）。
- DSH：0 字节的同步状态文件按空状态启动，不再让 Connector 启动即退出；非空的损坏文件仍会报错，不会被自动覆盖，插件提示到「设置 → 维护」移走该文件。启动前诊断保留连接阶段的失败快照，账号请求区分取消与 20 秒超时（#432）。
- DSH 插件：「设置 → 维护」新增「重装依赖环境」。依赖下载中断或环境损坏时，可以删除插件的 `connector-venv` 和项目副本后重新安装，进行中的安装会被中断；账号、设备绑定、同步缓存和设置保留，uv 全局缓存只清理未完成的下载。连接出错时设置页会提示切换 PyPI 镜像或重装依赖环境（#452）。
- DSH：「启动前诊断」可以展开查看插件和 Bridge 启动失败的错误码、脱敏调用栈和原因链；Connector 未启动或本地日志目录不可读时同样可用（#369）。
- DSH：插件启动 Connector 时把子进程 `NO_PROXY` 中的 `[::1]` 规范化为 `::1`；`contentHash` 按实际 JSON 传输语义规范化内容后再计算，JS 与 Python 两侧算出的哈希保持一致（#373）。
- DSH：插件能识别通过 `./desktop-local-up.sh` 启动的本地开发版 Desktop；Desktop 在配对或启动过程中介入时，插件会让出 Connector（#366）。README 注明只有开源的 anywhere-labs/dsh-desktop 内置本插件，DeepSeek 官方的 DeepSeek Harness Desktop 不内置（#388）。插件的测试基线升到 DSH 0.2.1-rc.2（#387）。
- DSH 插件：所选 PyPI 镜像改为 uv 的首选源，官方 PyPI 作为后备，镜像里没有的包会改从 PyPI 下载。清华、中科大、北外镜像上没有 `openai-codex`，以前选它们时 Connector 必然安装失败。规则与 Desktop 相同。
- Web / Desktop / Android / iOS：模型目录有两个及以上供应商时，模型选择器按供应商分组，组内的行不再重复供应商名，选中后输入框上仍显示带供应商的完整名称；Android 会话设置面板按模型 ID 归并，同名模型不再被合成一行（#411；iOS 为 #449）。
- Web / Desktop：会话创建失败后，草稿、附件和创建请求保留在工作区。`runtime_starting` 失败可以手动重试或返回编辑；重试前重新校验模型、权限和 Agent 模式，失效时保留输入并提示补选，不自动替换用户的选择。DSH 模型目录未就绪时禁止提交（#368）。
- Web / Desktop：事件补拉成功后重新读取运行状态，修复快速回复已完成却仍显示「正在工作」的问题（#303）。运行状态与能力信息并行读取、分别处理失败；Connector 离线时读取 Server 最后持有的状态；更旧的状态不会覆盖新状态，切换会话后不再应用过时的读取结果（#393）。
- Web / Desktop / Android：降低长会话流式更新和历史渲染的开销。单条正文更新只替换对应项，DSH 去重从最坏 O(N²) 降到 O(N)，历史 Markdown 与审阅结果可以复用（#394，见[性能说明](../performance/streaming-timeline-83.md)）。
- Web / Desktop：聊天代码块、工具输出和配对命令块统一为 shadcn Code Block，仍使用 highlight.js；修复开启「减少动态效果」时 Mermaid 图异常放大、初始视口空白的问题（#436）。
- Web / Desktop：多个项目的任务并行运行时，侧边栏项目不再反复换位（#311）；置顶和取消置顶使用不同的图标，iOS 同步修改（#162）。Web 的浏览器标签页图标跟随系统亮暗色切换（#401）。
- Desktop：把本地文件夹拖到侧边栏即可在本机 Connector 上创建项目；Web 不提供这个功能（#82）。设置页日志面板支持按全部 / Connector / Bridge 筛选；启动冲突与启动失败弹窗显示具体诊断，并可复制错误或打开日志文件夹（#365）。
- Desktop：Connector 运行环境准备失败（下载 Python 或依赖失败）时，启动弹窗可以直接切换 PyPI 镜像和 Python 下载镜像，也可以「清空缓存并重试」：删除 venv，安装包还会删除 uv 缓存和展开的 Connector 源码，凭据和设置保留。所选 PyPI 镜像改为 uv 的首选源、官方 PyPI 作为后备，镜像里没有的包会改从 PyPI 下载；清华、中科大、北外镜像没有 `openai-codex`，以前选它们必然安装失败。Connector 的 `pyproject.toml` 不再强制从 PyPI 下载 `meshcall`。上次同步失败、只留下空 venv 时，下次启动按首次准备处理，使用 15 分钟的超时并显示准备进度，不再用 30 秒超时。

## 已知限制

- MeshCall 0.3.0 为本仓库依赖的精确版本；升级需要单独评估（0.2 → 0.3 为破坏性更新）。
- Windows 命名管道路径与 Router 子进程（`--shutdown-on-stdin-close`、未签名二进制被安全软件拦截）需要在真机验证。
- 会话创建失败时，Android 和 iOS 走现有的 HTTP 失败分支，没有 Web / Desktop 的草稿恢复界面；未升级的 Bridge 缺少确定的接收证据时，Server 按结果未知处理（#368）。
- #393 只修正客户端读取运行状态的时序，没有改动 Server 快照、状态缓存和事件补拉的实现，这些路径内部的并发一致性窗口仍然存在。
- 代码块内容变化时仍同步高亮全文，内容很大时仍可能阻塞主线程（#436）。
- Codex 会话权限只从 rollout 文件的最后 1 MiB 读取。如果一轮里的工具输出很大，把本轮的 `turn_context` 推到这个范围之外，权限就会显示为「未同步」（#445）。
- 当 Codex Desktop 担任 IPC 路由时，曾有一次写入在 3 秒内没有收到任何回应，原因还没查明，#446 只增加了诊断日志。AA 与 Desktop 在同一会话里来回对话的完整流程还需要真机验证。
