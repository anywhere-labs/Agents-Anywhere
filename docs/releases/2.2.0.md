# 2.2.0：原生状态驱动的项目同步

- DSH、Codex、Claude Code 当前原生状态决定项目和会话归属；目录观察在工作设备完成。
- 同名、同目录、不同 Runtime 实例项目独立；移除 AA 原生项目改名及目录修改入口，保留置顶和用户归档。
- 项目/目录默认 30 秒、完整成员默认 5 分钟独立核对，事件与手动刷新进入统一队列；正文历史同步独立。
- AA 创建项目绑定 Runtime 与幂等请求 ID；原生成功回读后展示，超时保留未知状态。Claude 通过首次对话形成目录项目。
- 四端展示来源、核对时间和未分组原因；有效原生空项目可见。
- 接口版本全端 2.2.0；升级与回退见[升级指南](../upgrading.md)和[同步契约](../api/project-archiving.md)。

本说明描述实现；检查结果、规模观测及尚未完成的真实 Runtime/四端验收见[本轮验证记录](../migrations/native-project-sync-2.2-validation.md)。

## 项目同步评审修复

- 清除 Runtime 实例时同时退役该来源的项目和同步快照，迟到上传不能恢复已退役来源。
- 区分来源状态和逐根目录状态；多根项目可在已确认正常的目录中创建会话，异常根目录不会误拦截其他目录。
- 工作区同步采用独立来源锁，设备生命周期锁仅用于短时准入；历史上传及其他来源的 HTTP 上报不再等待整轮工作区应用。
- Codex 项目能力按实际实例协议公布，区分不支持与暂时故障。不支持的实例停止周期重试，并提示升级项目协议。
- 创建操作可跨页面和应用重启恢复。各端提供继续核对及明确再次新建，成功结果在客户端确认收到之前仍保留恢复入口。

- 创建与 Runtime 启动完成后的目录刷新提示失败，不再把已完成操作返回为失败。
- Codex 版本探测在 POSIX 系统上超时会同时清理启动器的子进程，避免异常启动器耗尽进程资源。
