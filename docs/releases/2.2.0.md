# Agents Anywhere 2.2.0

2.2.0 是一次接口更新（MINOR），发布于 2026-11-14，标签 `v2.2.0`。相对标签 [v2.1.0](https://github.com/anywhere-labs/Agents-Anywhere/releases/tag/v2.1.0)，本版包含可发现的 Runtime 类型与平台协议 1.1、工作区准备与异步创建（`contracts/runtime-workflows/1.1`，ACP 使用 1.2）、Pi ACP、Codex / Claude Code / DSH 的统一原生 Plan、Codex / Claude Code 的统一目标模式、模型渠道与 Tokens Anywhere 登录和链接、管理看板按小时汇总的使用统计、会话列表不再逐个查询最新记录，以及 DSH 大历史同步和附件传输的行为变化。按[版本号规则](../versioning.md)，所有端的版本号统一升到 2.2.0。面向用户的变化摘要见 [CHANGELOG](../../CHANGELOG.md)，本文记录接口变化、各端最低配套版本、数据库迁移、已知限制和安装包。

与上一版的差异：<https://github.com/anywhere-labs/Agents-Anywhere/compare/v2.1.0...v2.2.0>。

## 不在这次切分

- Tokens Anywhere：用 Agents Anywhere 账号登录、链接账户、模型网关和内嵌控制台（`POST /api/v2/integrations/tokens/embed-ticket`，[#598](https://github.com/anywhere-labs/Agents-Anywhere/pull/598)）都在本版代码里，默认关闭，见下文环境变量。Agents Anywhere 云端这一版不开启。云端与自部署实例的端到端联调由 [#510](https://github.com/anywhere-labs/Agents-Anywhere/issues/510) 跟踪，Tokens Anywhere 国内站与国际站双站授权在后续版本。

## 接口变化

- **平台协议 1.1**（[contracts/protocol/1.1](../../contracts/protocol/1.1/README.md)）：握手里的 Runtime 身份改为可发现的提供方键（规范化字符串），不再使用 1.0 写死的 `codex` / `claude` / `opencode` / `acp` / `dsh` 枚举。事件信封的 `protocolVersion` 接受 `1.0` 和 `1.1`。Server 仍同时接受 1.0 与 1.1；Web / Desktop 的生成类型在 `v1_1`，并继续读取 1.0 事件。1.0 已有事件产物保持冻结。
- **计划契约**加在 `contracts/protocol/1.0`：新增 `PlanningRequest`、`PlanningResponse`、`PlanningState`、`PlanDocument`。用法见 [统一原生 Plan](../api/planning.md)。
- **Runtime 工作流 1.1**（[contracts/runtime-workflows/1.1](../../contracts/runtime-workflows/1.1/README.md)）：工作区准备和异步创建不再借用 SessionNotice。

  | HTTP | 路径 | 行为 |
  | --- | --- | --- |
  | POST | `/api/v2/runtime-workflows/preparations` | 准备；HTTP 202，无平台会话 |
  | POST | `/api/v2/runtime-workflows/creations` | 预留、分配平台会话并开始创建；HTTP 202 |
  | GET | `/api/v2/runtime-workflows/{kind}/{id}` | 查询准备或创建；`kind` 为 `preparation` / `creation` |
  | POST | `/api/v2/runtime-workflows/{kind}/{id}/responses` | 按请求版本、代际和回答身份回答 |
  | POST | `/api/v2/runtime-workflows/{kind}/{id}/cancel` | 取消；已准入消息使用会话中断 |

  操作归属用户、设备、实例和项目。客户端不能覆盖 cwd、运行类型或平台会话 ID。同一创建 ID 重试只返回同一平台身份，内容不同则冲突。一次准备只能绑定一个创建。网络超时不当作消息未准入。Runtime 明确报告没有预留时，创建进入 `phase=rejected`，并在同一事务中释放这次准备。
- **Runtime 工作流 1.2**（[contracts/runtime-workflows/1.2](../../contracts/runtime-workflows/1.2/README.md)）：在 1.1 上增加可选 `configuration`（`Record<string, string | boolean>`），为首条消息冻结 Agent 通用配置。未提供时保持旧请求摘要；准备预留与正式创建必须使用同一配置。响应允许 1.1 和 1.2。`state.catalog` 复用主协议的模型目录，名称使用 `displayName`；非法目录返回 `502 invalid_runtime_response`，不会保存或下发。创建请求接受与普通新建会话相同的可选 `attachments`（最多 10 个、合计 32 MiB）。ACP 工作流使用 1.2。
- **会话上的工作流操作**（同一前缀 `/api/v2/runtime-workflows`）：
  - `GET` / `POST /sessions/{id}/configuration`
  - `GET /sessions/{id}/tree`
  - `POST /sessions/{id}/position`
  - `POST /sessions/{id}/close`
  - `POST /sessions/{id}/operations`（HTTP 202）
  - `POST /sessions/{id}/recover`（HTTP 202）

  Pi 的「继续任务」走 `recover`。除 `operationId`、`expectedGeneration` 外，可带 `cliExited` 和 `sourceRevision`。Pi 原生来源要求 `cliExited=true`，并且 `sourceRevision` 与索引修订一致。细节见 [Pi 原生历史](../api/pi-native-history.md)。ACP 侧的操作身份、代际和结果 phase 见 [acp-runtime 1.1](../../contracts/acp-runtime/1.1/README.md)；配置与表单形状见 [acp-runtime 1.0](../../contracts/acp-runtime/1.0/README.md)。
- **统一 Plan**（[#490](https://github.com/anywhere-labs/Agents-Anywhere/pull/490)）：`/api/v2` 下新增
  - `GET /sessions/{id}/planning`
  - `POST /sessions/{id}/planning`
  - `GET /sessions/{id}/planning/operations/{operationId}`
  - `GET /sessions/{id}/plans`
  - `GET /sessions/{id}/plans/{planId}/{revision}`
  - `GET /sessions/{id}/plans/{planId}/{revision}/markdown`

  写操作需要接管和 `session.planning`；审阅另需 `session.plan_review`。`session.plan_document` 声明文档能力。离线读取已保存正文不依赖原生能力，状态为 `stale` 时不能审阅。新建任务在既有 create-and-start 请求中携带 `planningIntent: {mode: "plan", operationId}`。命令为 `enter_plan`、`exit_plan`、`submit_task`、`approve_and_execute`、`request_revision`、`dismiss_review`。Connector 发布 `session.planning.updated`，Server 映射为 `planning.state.updated`。缺少这些能力的 2.1.0 客户端保持原有会话，不会打开 Plan。
- **错误文案**：Runtime、工作流和原生历史的失败带稳定 `code`。中英文文案在 [contracts/runtime-errors/1.0](../../contracts/runtime-errors/1.0/README.md)，由脚本生成到 Web、Desktop、Android 和 iOS。客户端不直接显示 Server / Connector 的 `message`。ACP Agent 新增通用错误码：`agent_cli_missing`、`agent_cli_unsupported`、`agent_acp_unavailable`、`agent_version_unsupported`、`agent_authentication_required`、`agent_session_failed`、`agent_session_unavailable`、`agent_steer_attachments_unsupported`、`image_input_unsupported`、`command_unavailable`、`invalid_command`；旧客户端不认识时显示 Connector 的中文文案。
- **附件**（[#492](https://github.com/anywhere-labs/Agents-Anywhere/pull/492)）：上传与下载改为流式处理。图片新增 `GET /api/v2/sessions/{id}/attachments/{fileId}/thumb`（宽度取 256 / 512 / 1024，返回 WebP）。不支持缩略图的文件返回 404。
- **时间线序号**（[#464](https://github.com/anywhere-labs/Agents-Anywhere/pull/464)）：`orderSeq` 必须落在 PostgreSQL `integer` 范围内（−2147483648–2147483647）。单条通知越界返回 HTTP 400 `invalid_order_seq`；混合批次只拒绝该条并继续处理其余通知。`timeline.sync` 任一条目越界则拒绝整条同步。DSH Bridge 1.0 的 timeline item schema 为 `orderSeq` 增加了同一上限。越界的历史缓冲会按原顺序移到时间线末尾；客户端收到 `session.refetch_required` 后，用修复前游标请求 `/events` 会得到 `snapshotRequired: true`。
- **ingest 拒收可重试**（[#535](https://github.com/anywhere-labs/Agents-Anywhere/pull/535)）：`POST /api/v2/connector/ingest` 响应的 `rejected[]` 每项新增 `retryable`（布尔）。等待会话锁超时（Redis 的 `session-revision` 锁或 PostgreSQL 的时间线写入锁）、数据库连接池用完、死锁和序列化失败标为 `true`，其他拒收为 `false`。一次响应里的拒收全部可重试时，Connector 按网络错误处理，原样重发整批：同步上传先重试 3 次，DSH 插件收到 `backend_unavailable` 后退避重发，后台上报保留在队首，Codex / Claude 历史会话不进入隔离。混合批次仍按永久拒收处理。旧 Server 不带这个字段，新 Connector 按 `false` 处理；旧 Connector 忽略它。见 [实时接口](../api/realtime.md)。
- **DSH Bridge 2.0** 在既有 MeshCall 通道上增加 `getPlanning` / `setPlanning`。只含运行中正文更新的连续批次，Connector 立即落库，但要满约 0.25 秒才返回，插件在等待期间合并后续片段。被拒收的会话在重新订阅或重建同步流之后仍然按退避重试，未到期时再次提交直接返回原来的隔离原因。完整快照编码后不超过 45 MiB 时一次提交，Server 只改写有变化的条目；超过 45 MiB 仍分页，`timeline.sync` 新增可选的 `snapshotRange {afterOrderSeq?, throughOrderSeq?}`，每页只替换自己覆盖的 `orderSeq` 区间，非法区间返回 HTTP 400 `invalid_snapshot_range`；旧 Server 忽略这个字段，仍按第一页替换、后续页追加处理。代理返回 413 时 Connector 缩小分页，最低 1 MiB。快照上传不再占用共享上传锁。见 [快照上传](../dsh-snapshot-uploads.md) 和 [Bridge 2.0](../../contracts/dsh-bridge/2.0/README.md)。
- **Pi**（[#484](https://github.com/anywhere-labs/Agents-Anywhere/pull/484)、[#509](https://github.com/anywhere-labs/Agents-Anywhere/pull/509)）：执行优先使用本机已安装的 `pi`（1.2.0 及之后的 1.x）提供的 SDK、依赖、配置和认证。已有受管模型网关配置保持隔离。有效能力 `session.recover` 提供「继续任务」，`session.close` 保留结束 AA 执行的能力。图片能力通过 `metadata.inputModalities` 与模型选项上的 `_meta.aa.modelInputModalities` 声明；省略表示尚未提供，不能推断支持图片。不支持的图片返回 `image_input_unsupported`。
- **统一目标模式**（[#539](https://github.com/anywhere-labs/Agents-Anywhere/pull/539)）：`/api/v2` 下新增 `GET` / `POST /sessions/{id}/goal` 和 `GET /sessions/{id}/goal/operations/{operationId}`。新建任务在既有 create-and-start 请求中携带 `goalIntent: {mode: "goal", operationId}`。Connector 发布 `session.goal.updated`，Server 映射为 `goal.state.updated`。旧 Connector 不声明 `session.goal`。细节见 [统一目标模式](../api/goals.md)。需要迁移 `v2_47`。
- **会话来源时间**（[#557](https://github.com/anywhere-labs/Agents-Anywhere/pull/557)）：`sourceAvailabilityUpdatedAt` 改为来源状态最后一次写入的时间，不再随每次清单扫描刷新。需要迁移 `v2_49`。
- **模型渠道**（[#515](https://github.com/anywhere-labs/Agents-Anywhere/pull/515)、[#571](https://github.com/anywhere-labs/Agents-Anywhere/pull/571)）：`/api/v2` 下新增模型配置、当前渠道和 Tokens Anywhere 链接，见 [模型配置 API](../api/model-config.md)。Runtime 配置里的模型网关 Key 改为只写：读接口和实时快照不再返回 `apiKey`，只返回 `keyHint` 或 `secretFields` 里的 `hint`。省略 Key 且地址的 host 不变时保留原 Key；换了 host 却没有新 Key 时返回 422 `secret_required`。旧版客户端编辑这类配置时需要重新填写 Key。缺少 `channelReconcileFence` 的 Connector 保留原配置并提示升级，不执行兼容切换。
- **用 Agents Anywhere 账号登录 Tokens Anywhere**（[#571](https://github.com/anywhere-labs/Agents-Anywhere/pull/571)）：新增机密客户端 `tokens-anywhere`。`GET /api/v2/oauth/authorize` 把浏览器转到 Web 的「登录 Tokens Anywhere」确认页，这一步不签发授权码；`POST /api/v2/oauth/authorize` 记录同意或拒绝。`POST /api/v2/oauth/token` 校验客户端密钥和 PKCE，签发 300 秒的 profile token，只能用于 `GET /api/v2/oauth/userinfo`。userinfo 返回 `userid`、`name`、`avatar`，带 `email` scope 时还有 `email` 和 `email_verified`。确认之后才向 Tokens Anywhere 提供名称、邮箱和头像；选「取消」则不提供。两个客户端环境变量都未设置时，这个客户端关闭。
- **使用统计**（[#472](https://github.com/anywhere-labs/Agents-Anywhere/pull/472)、[#473](https://github.com/anywhere-labs/Agents-Anywhere/pull/473)）：`GET /api/v2/admin/usage/report` 的计数改为读取按小时汇总。轮次耗时和审批等待的 p50 / p90 / p99 改为统计范围内的全部样本（`percentile_disc`），不再只取最新的 20 万条。分位数仍直接读使用事件，不能放进小时汇总。见 [Admin Usage API](../api/admin-usage.md)。需要迁移 `v2_53`。

新增和收紧的 Server 环境变量见「Server 与数据库」。Connector 仍依赖 `meshcall==0.3.0`。

| Web | 2.2.0 | 计划卡片与阅读器、目标模式、模型渠道、Pi、工作流创建和错误码文案；2.1.0 页面没有这些入口 |

| Connector | 2.2.0 | Pi ACP、Plan 与目标模式的原生适配、模型渠道、工作流和 DSH 快照行为。使用这些新行为时须与 2.2.0 Server 一起升级。旧 Connector 不声明目标能力；模型渠道会保留原配置并提示升级 |

## 产品变化

用户能看到的条目在 [CHANGELOG](../../CHANGELOG.md)。这里只记和升级有关的范围：

- Codex、Claude Code 和 DSH 可以用 `/plan`、`/plan <任务>` 和 `/plan off`。四端在输入区审阅计划，计划按不可变版本保存在 Server，设备离线仍可查阅。
- Codex 和 Claude Code 可以用 `/goal` 设置目标，在输入区上方编辑、暂停、恢复或清除。需要迁移 `v2_47`，并一起升级 Connector 和客户端；旧 Connector 不声明目标能力。（[#539](https://github.com/anywhere-labs/Agents-Anywhere/pull/539)）
- 「设置 → 模型渠道」可以选择默认渠道，也可以手动添加模型服务。Tokens Anywhere 可以用 Agents Anywhere 账号登录：部署者设置 `AGENT_SERVER_TOKENS_ANYWHERE_CLIENT_SECRET` 和 `AGENT_SERVER_TOKENS_ANYWHERE_REDIRECT_URI` 后开启。链接账户需要 `AGENT_SERVER_TOKENS_URL`（或由管理员在「管理 → 常规」填写）和 `AGENT_SERVER_PUBLIC_ORIGIN`。模型网关的 Key 保存后接口不再返回，旧版客户端编辑时需要重新填写。（[#515](https://github.com/anywhere-labs/Agents-Anywhere/pull/515)、[#571](https://github.com/anywhere-labs/Agents-Anywhere/pull/571)）
- 管理看板的使用报表改为读取按小时的汇总。轮次耗时和审批等待分位数改为统计范围内的全部样本，不再只取最新的 20 万条。（[#472](https://github.com/anywhere-labs/Agents-Anywhere/pull/472)、[#473](https://github.com/anywhere-labs/Agents-Anywhere/pull/473)）
- Pi 出现在四端的会话列表里，可以浏览本机历史，退出对应 CLI 会话后「继续任务」。Desktop 在准备 Connector 时一并准备 Pi 适配器。
- DSH：45 MiB 以内的完整历史一次提交；更大的历史在代理拒收时自动缩小分页；流式回复大约每 0.25 秒提交一次；超大上传不再堵住同一设备上其他 Runtime 的实时消息。DSH 0.2.2 的 Computer Use 授权提问回到 AA，并且只能从给出的选项里选择。
- Codex、Claude Code：历史巡检的时间线改走与 DSH 相同的分页上传，45 MiB 以内一次提交，代理返回 413 时缩小分页（最低 1 MiB），状态和提醒随最后一页提交。完整快照分页时与 DSH 一样按 `snapshotRange` 区间替换；Claude 历史这类只含新增消息的部分快照每页都只追加，不带区间。仍被拒收（无法再切的 413、其他 4xx 或不可重试的 `rejected`）的会话只隔离它自己：约 10 分钟起逐次加倍、最长约 6 小时内不再读取和上传，期间只更新会话信息和状态。只改 Connector。（[#589](https://github.com/anywhere-labs/Agents-Anywhere/pull/589)）
- Android 可以在设备页添加和管理 Agent，会话里可以看 Markdown / HTML 图片和工作区截图。
- Web 在对话里已经选中文字时，右键使用浏览器自带菜单。

标签 `v2.1.0` 打出之后、源码版本号仍是 2.1.0 时，还有几项修正写进了 CHANGELOG 的 2.1.0 节，它们包含在上面的比较链接里：升级后同 revision 的模型目录不再被误判为冲突（[#463](https://github.com/anywhere-labs/Agents-Anywhere/pull/463)）；被 Codex App 持有的会话执行 `/compact` 时转交 App（[#506](https://github.com/anywhere-labs/Agents-Anywhere/pull/506)）；跳过引导或进入主界面仍没有 Agent 时提醒添加（[#513](https://github.com/anywhere-labs/Agents-Anywhere/pull/513)）。

## Server 与数据库

2.2.0 的数据库 revision 为 `v2_55`（schema version `2.55`，源码中的 `CURRENT_SCHEMA_REVISION`）。从 2.1.0（`v2_44`）升级会依次执行：

- `v2_45`：新建 `runtime_workflows`、`session_runtime_event_receipts`，保存工作区准备、异步创建和运行时事件回执。不回填历史工作流。
- `v2_46`：新建 `planning_creations`、`session_planning`、`plan_documents`、`planning_operations`，保存计划的当前投影、不可变正文、操作回执和创建身份。不回填历史计划。
- `v2_47`：新建 `session_goals`、`session_goal_state`、`goal_operations`、`goal_event_outbox`，保存统一目标模式的当前状态、操作回执和待投递事件。只新增表，旧会话不回填。（[#539](https://github.com/anywhere-labs/Agents-Anywhere/pull/539)）
- `v2_48`：删除 `timeline_items` 上自 2.1.0 起不再被查询使用的 `idx_timeline_items_item_time_type_role`，并为 `connectors(user_id, revoked)` 建立 `idx_connectors_user_revoked`。两步使用 `DROP INDEX IF EXISTS` 和 `CREATE INDEX IF NOT EXISTS`，已经手工完成的数据库执行后不变。与其他 revision 在同一事务里执行，不使用 `CONCURRENTLY`，请在停止所有 Server 和 worker 的维护窗口里运行。回滚到 `v2_47` 会重建时间线索引，大库上耗时很长。（[#553](https://github.com/anywhere-labs/Agents-Anywhere/pull/553)）
- `v2_49`：新增 `session_inventory_scans`，并给 `sessions` 增加可空列 `source_changed_seq`（已有行保持 `NULL`，不重写这张大表）。内容没有变化的清单扫描不再改写 `sessions` 行。`source_scan_token` 保留以便回滚，新版 Server 不再读写它。（[#557](https://github.com/anywhere-labs/Agents-Anywhere/pull/557)）
- `v2_50`：给 `device_runtimes` 增加 `model_connection_json`、`managed_by`；新建 `tokens_links`、`tokens_link_states`、`model_profiles`、`runtime_model_assignments`、`model_config_operations`，保存模型连接报告、模型配置和 Tokens Anywhere 链接。
- `v2_51`：删除 `model_config_operations`，改为用户的当前渠道：新建 `model_channel_selections`、`runtime_channel_overrides`、`runtime_channel_switches`、`runtime_admissions`。
- `v2_52`：给模型配置和渠道切换补上连接版本与对账字段，新建 `runtime_channel_sync`、`channel_sync_outbox`、`channel_device_fences`、`channel_rotation_intents`、`channel_device_gates`，用于渠道对账和通知。已有对账数据或未完成的切换快照时，降级会拒绝，需要先停掉渠道 worker 并导出这些数据；空库可以降级。（[#515](https://github.com/anywhere-labs/Agents-Anywhere/pull/515)、[#571](https://github.com/anywhere-labs/Agents-Anywhere/pull/571)）
- `v2_53`：新建按小时汇总使用事件的表 `usage_hourly_counts`、`usage_hourly_users`、`usage_hourly_sessions`、`usage_hourly_runtime_sessions`、`usage_hourly_runtime_users`、`usage_hourly_connectors`，并按已经记录的使用事件回填。事件多的实例这一步会更久，请在停止所有 Server 和 worker 的维护窗口里执行。之后每次写入使用事件都会在同一事务里更新这些汇总。分位数不写入这些表。（[#472](https://github.com/anywhere-labs/Agents-Anywhere/pull/472)、[#473](https://github.com/anywhere-labs/Agents-Anywhere/pull/473)）
- `v2_54`：给 `sessions` 增加 `latest_item_id`、`latest_item_time`、`latest_item_order_seq`、`latest_item_updated_seq`、`latest_item_at`，记下每个会话最新一条时间线记录的摘要，并从已有数据回填。回填对每个有时间线的会话经 `idx_timeline_items_session_latest` 读一条最新记录并解析其 `payload_json`，耗时随会话数增长，与 `timeline_items` 的总大小无关；会改写 `sessions` 的每一行。之后时间线写入在同一事务里更新这些列，会话列表只读它们，不再逐个查询 `timeline_items`。请在停止所有 Server 和 worker 的维护窗口里执行：回填期间提交的时间线写入要等该会话下次写入才会反映。（[#595](https://github.com/anywhere-labs/Agents-Anywhere/pull/595)）
- `v2_55`：给 `connectors` 增加可空列 `device_settings`，保存用户为某台设备选择的行为开关（例如 Desktop 关机时是否询问）。不改写已有行，`NULL` 表示全部使用默认值。（[#596](https://github.com/anywhere-labs/Agents-Anywhere/pull/596)）

`v2_50` 至 `v2_52` 的部署顺序：先停止旧 Server worker，执行迁移，再启动新 Server，然后升级 Connector。保存手动填写的 Key 或链接 Tokens Anywhere 之前，`AGENT_SERVER_SECRET` 至少 32 个字符，且不能仍是开发默认值 `agent-server-dev-secret`。旧 Connector 会保留原配置并提示升级。已经执行过模型配置分支旧编号 `v2_47`–`v2_49` 的数据库不能直接套用现在的编号，需要从 main 的 `v2_49` 或空库升级。

升级步骤见[升级指南](../upgrading.md)。不要让 2.1.0 Server 连接已经迁到 `v2_55` 的数据库。

自 2.1.0 起新增或收紧的环境变量：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `AGENT_SERVER_SECRET` | 开发默认值 `agent-server-dev-secret` | 原用于签发登录令牌。现在也派生加密模型 Key 和 Tokens Anywhere refresh token 的密钥。保存手动 Key 或链接账户前必须至少 32 个字符，且不能仍是开发默认值；否则相关写接口返回 409 `secret_unconfigured`。更换后已保存的密文无法解密。开启 Tokens Anywhere 登录客户端时同样要求至少 32 个字符 |
| `AGENT_SERVER_PUBLIC_ORIGIN` | 未设置时回退到反向代理头或请求 URL | 实例对外的 origin，例如 `https://agents.example.com`。Tokens Anywhere 用它识别实例并拼出回调地址，链接前应设好 |
| `AGENT_SERVER_TOKENS_URL` | 未设置 | 链接用的 Tokens Anywhere origin，必须与 Tokens 的 `TOKENS_PUBLIC_ORIGIN` 完全一致。管理员可以在「管理 → 常规」覆盖。两者都没有，或值不是 origin 时，链接保持关闭。Tokens 一侧还要设置 `TOKENS_SECRETS_KEY`，否则托管 Key 的明文只在创建时返回一次，AA 之后取回会得到 409 `key_not_kept` |
| `AGENT_SERVER_ALLOW_PRIVATE_MODEL_GATEWAYS` | 关闭 | 设为 `1`、`true` 或 `yes` 后，按地址添加模型服务时允许识别内网、回环和链路本地地址。关闭时这些地址要改为手动选择协议 |
| `AGENT_SERVER_TOKENS_ANYWHERE_CLIENT_SECRET` | 未设置 | 「使用 Agents Anywhere 登录」的客户端密钥，至少 32 个字符。与下面的回调地址都未设置时，该客户端关闭。只设置其中一个，或密钥短于 32 个字符、回调不是精确 HTTPS（本机 http 回环除外）时，授权请求会失败 |
| `AGENT_SERVER_TOKENS_ANYWHERE_REDIRECT_URI` | 未设置 | Tokens Anywhere 的精确回调 URL。须为 HTTPS，不能带用户信息、query、fragment 或空白。本机开发可以用 `http://localhost`、`http://127.0.0.1` 或 `http://[::1]` |
| `AGENT_SERVER_DASHBOARD_MIN_INTERVAL_SECONDS` | `2` | 同一用户在一个 worker 上，连续的看板快照至少间隔这么多秒才再推一次。`0` 表示每次变化都推送。（[#552](https://github.com/anywhere-labs/Agents-Anywhere/pull/552)） |
| `AGENT_SERVER_MALLOC_TRIM_INTERVAL_SECONDS` | 不开启 | 设为秒数（至少 30，例如 `300`）后，每个工作进程定期把已释放的内存还给系统，用于长时间运行时内存缓慢上涨的部署。（[#586](https://github.com/anywhere-labs/Agents-Anywhere/pull/586)、[#616](https://github.com/anywhere-labs/Agents-Anywhere/pull/616)） |

## 已知限制

- DSH 的 Plan 必须组合原生 Plan 插件。已演练 `@deepseek-ai/dsh-plan-mode@0.2.0-rc.2`。该版本取消审阅会产生工具错误，因此「暂不执行」用原生回合取消结束等待。
- Codex 不支持在一轮还在跑的时候切换规划模式，这种切换会被明确拒绝。
- Pi：四端暂不展示 AA 已接手时的状态卡片和其中的「结束 AA 执行」。原地恢复只开放不需要历史格式迁移的兼容格式。原版 CLI 不受 AA 的锁约束，来源冲突检测不是文件系统级独占。
- 超过 45 MiB 的 DSH 快照仍然分页，各页之间没有跨页事务：中途失败时已接受的页已生效，其余部分保留上一次的内容。只有 Server 和 Connector 都是 2.2.0 时才按区间替换；任一端较旧时，第一页被接受到最后一页落库之间，Server 上可能只有前半段历史，第一页之后的历史也会被删掉再写回。
- Codex、Claude Code 历史里单条记录就超过入口上限时仍然同步不了，会话停在退避里；四端还没有「该会话过大，未同步」的提示，只在 Connector 日志里记一条警告。退避状态只在内存里，Connector 重启后会重新尝试一次。
- Computer Use 的授权提问只能从给出的选项中选择。
- 应用内「立即更新」在新安装包上传到官网之前，拿到的仍是站点上现有的安装包。
