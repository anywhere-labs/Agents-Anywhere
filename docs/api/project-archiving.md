# 原生工作区同步与项目归档（#301）

本次修改纳入 2.1.0 发布批次，修改 Server、Connector、DSH 插件和 Android。沿用现有 AA 项目删除、会话归档接口，不增加删除入口、删除查询参数或客户端响应字段。数据库新增 `v2_45`，保存设备各 Runtime 最后确认的工作区成员清单。DSH 和具备原生项目能力的 Codex 使用成员清单；Claude 保持原有最近会话发现与 cwd 分组，不新增完整历史扫描或来源缺失对账。

## 用户可见行为

| DSH 中的操作 | AA 中的结果 |
| --- | --- |
| 登记工作区并添加会话 | 根据原生工作区身份和成员列表建立项目归属，不以会话 cwd 推断成员 |
| 移除工作区登记，但保留对话日志 | 对应 DSH 会话转入未分组；已归档会话仍归档，历史与附件保留 |
| 在同一目录重建工作区 | 只关联新工作区实际包含的会话，不自动带回旧对话；不重复创建同设备同目录的 AA 项目记录 |
| 在重建工作区中新建对话 | 新对话正常显示，不继承旧对话的归档状态 |
| 插件读取失败、断线或清单非法 | 保留最后一次有效清单，不将失败当成空集合解除归属 |
| 在 AA 主动归档 | 继续使用原有归档逻辑；普通同步、工作区重建不取消旧会话的 AA 归档 |

AA 项目仍可被多个 Runtime 共用。成员变化只影响对应设备、对应 Runtime 的会话，不能解除其他 Runtime 或设备的项目绑定。用户在 AA 主动创建或改名的项目元数据继续保留；移除 DSH 工作区不删除 AA 项目记录、本机文件或任何会话历史。空项目展示继续受现有客户端筛选规则影响。

Android 项目视图新增未分组分区，复用原会话行、设备/Runtime 筛选、归档状态筛选、置顶及会话操作。Web、Desktop、iOS 使用已有的未分组展示。

## 删除和归档接口保持现状

- `DELETE /api/v2/projects/{projectId}` 仅允许删除没有关联会话的项目；已归档会话也计入关联数量，非空项目返回 409。没有新增 `detachSessions` 参数。
- `POST /api/v2/projects/{projectId}/sessions/archive-all` 继续接受 `archived: true, scope: "all"`。来源已 missing、deleted 或 unavailable 的关联会话也可归档，无需请求本机 DSH。
- 项目归档仍是批量归档会话、清除项目的 `manuallyCreated` 标记，不删除项目或解除会话绑定，不调用 DSH 工作区删除 RPC。
- 在 AA 重用一个仍关联旧会话、且旧会话全部已归档的项目时，不重新开启手动空项目的展示例外。旧会话保持归档；新会话或用户主动取消归档仍可让项目正常出现。

## 数据路径

1. DSH 插件从 `workspaceRegistry` 同步读取 `{id, title, path, sessionIds}` 完整清单。初次会话同步前发送一次；登记、成员或名称变化后发送更新。同一订阅中重复的相同清单不重复发送。
2. Connector 只转发明确标记 `version: 1, complete: true` 的 `workspace.inventory` 扩展，发布为 `runtime.workspaces.updated`。真实设备和 runtimeId 来自已认证的 Connector 及宿主绑定，不由清单自行指定。
3. Server 验证清单、路径唯一性和成员唯一性，在设备行锁保护下保存最后有效清单及原生工作区到 AA 项目的映射，并记录待应用会话和完成状态。过期快照不能覆盖更新快照；项目操作统一按设备、清单、项目的顺序加锁。
4. 已有会话通过原有会话 revision fence 更新归属；后续会话导入与快照更新也读取已确认清单。不在清单中的该 DSH Runtime 会话进入未分组，不再由孤儿 cwd 创建项目。该步骤只处理实际归属差异，不更改 cwd、AA 归档状态、Timeline 或附件。相同且已完成的清单不重新写入会话或触发列表失效；部分失败会在重试时继续补完，并发布此前已提交的归属变化。
5. Server 发布现有会话元数据更新及 `dashboard.changed`，各客户端复用原有刷新路径。

成员信息不触发从未导入的隐藏、空白或已归档会话的历史导入。没有任何有效原生清单的 Runtime 继续使用原有 cwd 分组规则；Codex 的能力门槛及 Claude 的保留行为见下文。

清单上限为 10000 个工作区、合计 50000 个成员及原有 6 MiB 批次限制。超限、部分、重复成员或非法路径不能提交成有效清单，不能截断后冒充完整快照。

## Codex 原生项目

Connector 通过实验性 `project/list` 读取项目身份、名称和根目录，并分页读取各来源类型的活跃、归档会话的 `projectId`。项目或成员变更通知触发刷新，周期同步负责补偿漏掉的通知。读取前后项目清单变化、重复分页、超限和读取错误都不能当成空清单提交。

Codex 的清单使用 `membershipScope: "tracked"`：只有明确出现过非空 `Thread.projectId` 的会话交给原生成员规则管理，其他旧会话继续按 cwd 分组。一条原生归属不会切换整个实例的旧历史。首次发现明确成员后保留清单读取的启用状态，从而能处理后续空清单；同时 Server 保留曾受原生管理的会话标识，移除归属后不再由 cwd 自动带回。这个边界不代表 Desktop 已完成全部历史迁移，也不操作或迁移用户本机项目。

| 原生 Codex 中的操作 | AA 中的结果（启用成员同步后） |
| --- | --- |
| 删除原生项目但保留会话 | 曾明确加入原生项目的原成员进入未分组；保留已同步历史、附件和 AA 归档状态 |
| 在同目录重建原生项目 | 使用新项目的实际成员，不按旧 cwd 带回旧会话 |
| 明确把旧会话加入新项目 | 更新项目归属，旧会话的 AA 归档不变 |
| 原生项目改名 | 同步由清单创建并管理的 AA 名称；用户在 AA 主动命名后不再覆盖 |
| 多根目录项目 | 按原生成员归到同一个 AA 项目；主根目录用于项目路径，各会话 cwd 保持原值 |

AA 项目仍以设备和路径复用记录，不能表达多个原生项目共用同一主路径的独立身份。此类清单会被整体拒绝，保留最后有效归属，不任意合并。Codex 原生接口可用性不等于当前 Desktop 界面已经使用它；本次不操作或迁移用户的 Codex 本机项目。

## Claude 保持原有同步策略

Claude 当前没有与 DSH 登记表等价的普通工作区身份及成员事件，因此继续按 cwd 分组。后台沿用每轮发现最近 100 条会话并合并本地缓存的策略；不增加 10000 条完整历史分页，不因本次工作区同步而批量导入更早历史。

本次也不为 Claude 增加完整会话来源对账：未出现在最近会话列表中的记录不能据此标记为 `missing`。删除工作目录、同目录重建或删除日志不会通过本次新增机制自动解除 AA 项目绑定；已同步历史及 AA 归档行为保持原样。SDK 内部可能仍扫描全部文件元数据后返回最近结果，本次不修改 SDK 的读取实现。

## 升级、兼容与回退

- 所有组件继续使用主线 2.1.0，不为此修复再次升到 2.2.0；同号早期构建不代表已包含本功能。
- 先升级 Server 并执行 `v2_45`，再升级 Connector；DSH 还需升级配套插件。Codex 原生能力由实际二进制与 SDK 决定；Claude 不需要本次同步适配。Android 更新后可在项目视图查看未分组对话。
- 旧 Connector 忽略新增扩展，未提供过有效清单的旧插件继续沿用原有 cwd 分组，不具备完整的成员同步效果。
- 已启用成员清单的 Runtime 应维持配套组件；降级插件后清单将不再更新，直到恢复兼容的插件，不能据此承诺分组仍实时一致。
- 回退应用不会删除会话历史。旧 Server 恢复按 cwd 分组后，后续同步可能重新关联孤儿目录。数据库降级只移除新增的清单表，已经保留的会话和历史不被删除。

## DSH 移除工作区为何会残留对话

当前依赖的 `@deepseek-ai/dsh-workspace@0.2.1-rc.2` 中，`WorkspaceRegistry.delete()` 只移除工作区登记，明确保留目录和会话日志，并不要求工作区为空。重新添加同一目录得到新的工作区身份，不自动带回旧会话。全局 `archivedSessionIds` 独立保存归档状态，移除、重建和重启宿主均不会清除旧会话的归档。

上述行为已通过当前 SDK 的隔离实例验证，并通过实际 DSH SDK → Connector 转发 → Server 的重建流程核对。它不能证明 #301 报告者旧桌面版本的具体操作路径；缺少当时版本源码和操作记录时，不把旧版本成因认定为已复现。
