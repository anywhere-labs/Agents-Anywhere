# Timeline 工具身份与多来源同步

## 修复说明

本次修复 Codex 工具在实时事件与原始历史回读之间的身份差异，Desktop 通过
内置 Connector 获得该修复。本次不调整组件版本号，正式发版版本由发布流程确定。
源码修复不表示制品已经发布或完成真实设备验收。

原始历史解析曾遗漏 `webSearch`、`mcpToolCall`、`dynamicToolCall` 和
`collabAgentToolCall` 的工具角色。例如同一个搜索被实时事件投影到
`tool:webSearch`，回读时却被投影到 `item:webSearch`。角色所在的 lane 参与
平台 ID 计算，因此 Server 会收到两个不同 ID。原始搜索解析同时没有读取
`query/action`，造成重复条目只有通用搜索文案。

修复统一原始和类型化搜索解析、角色推断及回退快照入口，沿用既有
`turn-item-v2` 身份算法。原生 `plan` 也统一为类型化 SDK 已使用的
`systemMessage` 投影，避免计划条目发生同类身份分裂。
活动回合中的稀疏搜索回读保留已知查询、操作和状态，
完整条目在发送前重新计算内容哈希。明确的空查询仍是空查询，不当作字段缺失。
活动快照也会为后续实时搜索恢复对应的位置和已知字段；回合结束释放缓存。

## 三种 Runtime 的责任

| Runtime | 工具业务身份 | 实时与历史的关系 |
| --- | --- | --- |
| Codex | 原生回合 + 类型/角色 lane + lane 内位置；保留原生 item ID 作为来源 | SDK 事件、原始历史、分页及 IPC 必须采用一致的角色和位置；分页截断在编号之后进行 |
| Claude | 原生会话作用域 + `tool_use_id` | 调用和结果共享 `ClaudeMessageProjector`；增量只包含结果时从完整历史查找调用上下文 |
| DSH | 原生会话 + `tool` 类型域 + `callId` | 流式、正式消息、调用、结果和历史重放共享投影器；被丢弃的草稿通过完整快照移除 |

各 Runtime 保留原有身份算法和字段格式。例如不能为统一角色值而改写 DSH 的
现有工具角色，也不能要求 Claude 的 `action` 与 Codex 使用同一种内部格式。

一次真实工具调用只对应一个工具条目；调用开始、结果完成和历史重放是该条目的
不同观察。相同查询词的两次调用应保留两项。查询正文、展示标题、事件名称、
内容哈希和传输批次都不能成为通用去重键。

## 公共链路与客户端

数据链路为 Runtime 投影 → Connector Host/队列 → WS 或 HTTP fallback →
Server 写缓冲/数据库 → 实时事件或历史快照 → Web、Desktop、Android、iOS。

- Runtime 负责生成稳定的平台 ID 和完整条目；`contentHash` 表示条目状态，
  不能用来合并不同身份的条目。
- Server 按 `(sessionId, id)` 写入。同一 ID、相同内容哈希的重放不应产生新项。
  Server 不解释各 Runtime 的私有身份规则，也不按查询词或来源原生 ID 猜测合并。
- `complete=false` 是增量同步，`complete=true` 是完整替换；完整替换的 reset fence
  必须阻止旧写缓冲恢复已移除的条目。业务拒绝不能被当作写入成功并提交检查点。
- 四端按平台 ID 与服务器更新序号合并，不加入按搜索内容过滤重复的 UI 规则。
  四端源码、无界面检查和实际设备操作是不同层级的证据。

## 升级边界

本次不改变 API、事件、数据库、跨端契约或 DSH 投影版本，不升级 Codex 同步检查点
版本，不通过强制全量同步清理旧数据。

保障范围是修复版本处理的新会话与有效原生 ID。已有重复不迁移、删除或合并；
旧会话重新同步仍可能因身份修正增加条目，完整快照也仍按既有替换语义工作。
旧 Connector 或旧 Desktop 内置 Connector 仍可能产生原问题。

Claude 缺少原生工具 ID 时的 `repr(block)` 兜底具有表示差异风险，本次不处理这类
异常输入。缺少原生身份的数据不能被归入“有效 ID 链路已验证”的结论。

发布前应分别提供三种 Runtime 的原生执行、历史重读、断线恢复和四端验收记录。
没有可用 Runtime、设备或构建工具链的项目须明确标记为受阻，不能用投影探针
或现有自动化检查代替真实验收。回滚使用上一版制品，不需要数据库迁移回滚。
