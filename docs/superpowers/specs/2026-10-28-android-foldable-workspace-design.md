# Android 折叠屏自适应会话工作台设计

日期：2026-10-28

状态：用户已确认方案 B 和首版范围；本文待最终审阅。

工作分支：`feat/apk/foldable-workspace`

## 1. 目标与已确认决策

让 Android 在展开的折叠屏、大窗口和横屏上具备类似 PC 的列表—详情交互：左侧项目 / 会话，右侧当前会话；窄窗口沿用手机单栏导航。用户选择了**方案 B：自适应双栏，且侧栏可以手动收起 / 展开**，并选择通用折叠屏适配，不绑定特定品牌。

完成条件是实际可操作的端到端功能，而非仅有布局外壳：左侧选择真实会话，右侧通过现有控制器加载并展示该会话，消息输入、发送、附件、审批、文件与终端继续使用原链路；提供可安装 Debug APK 以及明确的验证记录。

## 2. 方案比较与选择

- **方案 A：宽屏常驻侧栏。** 复用现有页面，状态较少，但看长代码时不能临时让出侧栏空间。
- **方案 B：宽屏双栏 + 手动收起。已选。** 在 A 基础上增加一个可恢复的侧栏显示状态，满足集中阅读需求，不重建业务体系。
- 不使用桌面网页嵌入、桌面代码移植或后端改造。现有 Compose 和系统窗口尺寸即可完成本次布局，不为固定布局添加一套通用布局框架。

## 3. 布局与交互

### 3.1 窗口规则

- 使用应用实际可用窗口宽度（dp），不根据机型名称、设备类别或单纯的横竖屏判断。
- 宽度 **>=600dp**：会话工作台启用双栏能力；宽度 **<600dp**：手机单栏。
- 展开侧栏约占窗口宽度的 36%，限定为 **240–320dp**；右侧占剩余空间。600dp 窗口下仍需确保两侧关键控件没有横向越界。
- 侧栏和右侧内容独立滚动；消息输入区维持在会话内容底部，并适配软键盘、安全区域和系统栏。
- 左侧复用现有项目 / 会话视图及其配置入口，不额外发明第三种业务列表。收紧必要的留白，保留现有设备、设置、新建等入口。

### 3.2 选择、收起与空态

- 宽屏点击左侧会话，更新现有选中会话与详情导航状态，只替换右侧会话，左侧保持可见；选中行有视觉高亮及可访问性选中语义。
- 侧栏可收起；收起后保留可触达的展开入口，不能让用户陷入无法重新选择会话的状态。按钮使用明确的内容描述及至少 48dp 触控目标。
- 同一账号的窗口缩放 / 旋转期间保留用户的宽屏收起偏好；进入窄屏不把它误作隐藏手机列表的指令，首次进入宽屏默认展开。退出账号不泄漏上一个账号的选中状态。
- 未选中会话时右侧显示选择会话提示，不自动开启任意会话或创建新会话。
- 新建项目、设备、账号、全局文件与终端等非工作台页面仍保留现有完整页面交互；不扩展为全应用桌面布局。

### 3.3 手机导航与返回

- 窄屏列表点击会话进入单独详情页；返回再选其他会话，维持现有手机导航。
- 从详情页展开窗口：当前详情进入右栏，不清空选中会话或草稿。从双栏折叠为窄屏：继续显示正在阅读的会话，而不是强制退回列表。
- 系统返回先服从现有会话内子页逻辑（例如从文件 / 终端返回消息），再返回会话列表。手动收起按钮只控制侧栏，不承担导航或更改选中会话。
- 宽屏返回列表后，右侧回到未选择提示；普通返回行为不改成关闭应用，也不加入新的跨会话历史栈。

## 4. 状态、数据流与实现边界

现有入口为 [AgentsAnywhereApp.kt](../../../android/app/src/main/java/com/agentsanywhere/app/app/AgentsAnywhereApp.kt)，由根状态持有 `selectedSessionId`、目标页面与新建草稿，现有 `onOpenSession` 同时处理打开详情和标记已读。[AgentsAnywhereNavHost.kt](../../../android/app/src/main/java/com/agentsanywhere/app/app/AgentsAnywhereNavHost.kt) 目前分别渲染 [HomeScreen.kt](../../../android/app/src/main/java/com/agentsanywhere/app/ui/screens/home/HomeScreen.kt) 与 [SessionDetailScreen.kt](../../../android/app/src/main/java/com/agentsanywhere/app/ui/screens/sessiondetail/SessionDetailScreen.kt)。

实施时在现有导航装配层增加工作台布局，继续调用现有真实回调，不新增会话数据源或更改 API：

`项目 / 会话行 → 现有 onOpenSession → 根选中状态 → 唯一详情页面 → 现有控制器 / 实时通道 → 消息与输入区`

- 避免宽屏点击会话触发整屏列表离场动画；避免同一会话因布局变化同时挂载两个活跃详情订阅。
- 会话输入草稿继续走现有按会话隔离的持久化草稿存储；待创建会话也使用现有新建草稿身份，不能与其他会话串用。
- 阅读位置、列表滚动和项目展开状态优先使用已有状态持有能力；按需要稳定 Compose 内容身份和保存 / 恢复边界，不另建消息缓存体系。
- 明确验证会话 A/B 切换、尺寸变化以及 Activity 重建时的会话身份、未发送文本与阅读位置；任何未验证项在交付记录中列出，不把已有代码推断当作测试通过。
- 详情头部当前含固定标题宽度，实施中允许将其改为在剩余空间内弹性布局，避免分栏后标题与操作按钮互相覆盖；保留原功能。
- 不修改协议、数据库、登录流程、权限策略、Runtime 能力判断、消息发送条件或真实设备参数。

## 5. 首版不包含

- 半折悬停的上下分区、实体遮挡铰链专门避让、跨铰链内容分区。
- 鼠标拖拽调宽、多窗口多会话、桌面式多标签、拖放附件等额外桌面功能。
- 官方签名、商店发布、应用标识或版本体系重设计。

本次以连续可用内屏为目标。若后续要求双实体屏 / 遮挡铰链或姿态感知，需要引入真实窗口特征数据并单独在对应硬件上验证；本次不声称覆盖这些姿态。

## 6. 测试与验收

### 6.1 自动检查

- 最小可运行测试覆盖 599dp / 600dp 分界、典型内屏与大窗口侧栏宽度、收起 / 展开及窄屏行为。
- 覆盖真实列表选择到详情的联动、选中状态、宽窄切换、草稿隔离 / 恢复；测试优先沿用现有 JUnit / Compose / Robolectric 能力，不为此引入测试框架。
- 运行本次新增 / 受影响的最窄测试，之后运行项目规定的 `./gradlew testDebugUnitTest assembleDebug`；遇到既有失败如实定位，不删除断言绕过。
- 适用时补充 Android 相关静态检查；不运行无关 Server / Web / Desktop 的全量检查。

### 6.2 界面验证矩阵

| 场景 | 验收重点 |
| --- | --- |
| 窄窗口 <600dp | 列表与详情单页导航；返回正常 |
| 窗口恰为 600dp | 双栏开启；关键控件可见且可触达 |
| 典型展开窗口约 700–850dp | 左侧项目 / 会话，右侧内容，独立滚动 |
| 大窗口 >=1000dp | 侧栏不无限变宽；会话使用剩余空间 |
| 收起 / 展开侧栏 | 内容继续可用；展开入口不丢失 |
| 选 A → 输入草稿 → 选 B → 回 A | 内容身份、选中高亮、草稿隔离与恢复 |
| 展开 / 折叠、旋转、系统分屏缩放 | 当前会话与草稿不清空，阅读位置恢复 |
| 打开键盘和会话内文件 / 终端页 | 输入区不被遮挡，返回优先退出子页 |

有可用手机模拟器时执行界面检查；只读环境探测发现现有 AVD 是车载设备，不能作为折叠屏验收证据。可补齐普通手机 / 可缩放模拟器并验证窗口大小，但没有真机时必须标注物理折叠、真实折痕与厂商键盘仍未验证。依赖服务器和账号的实时发送 / 审批，只有在实际执行后才能报告验证通过，不读取或捏造凭据。

## 7. 构建、交付与环境

- 使用现有 JDK 17 和 Android SDK，不修改全局 Java 或包管理器设置；构建进程显式设置路径。
- 已探测 JDK 17 可执行，SDK 目前只有 API 35；需补齐项目要求的 `platforms;android-36`，并允许 Gradle 下载缺失依赖。不能为了方便把 compileSdk / targetSdk 降到 35。
- Debug 包使用开发签名、现有应用标识，不读取官方签名密钥；它通常不能直接覆盖不同签名的官方包。若已有官方版本，先告知用户签名冲突；不擅自卸载应用或清空数据。
- 最终给出 APK 文件、SHA-256、构建与检查结果、安装注意事项和未验证范围，不把“生成 APK”描述成“真机全部通过”。
- 用户可感知的变化写入根 [CHANGELOG.md](../../../CHANGELOG.md) 顶部未发布的 Android 分类。预览线框图、临时日志、SDK、构建输出和签名文件不提交到源码仓库。
