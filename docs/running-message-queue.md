# 运行期间连续发送消息（#88）

Web 和 Desktop Workbench 的会话输入框在 Agent 运行期间支持两种发送方式：

- **排队等待**（默认）：保存消息、已上传附件和模型/权限选择；当前任务结束且会话恢复空闲后，按先入先出顺序逐条发送。
- **引导当前任务**：仅当当前会话的 `session.steer` 能力可用时启用，调用已有 `/runtime/steer` 接口，不启动新回合或修改当前回合的模型/权限。

Enter 使用当前选中的发送方式，Shift+Enter 换行；停止按钮仍可使用。没有引导能力的 Agent 只支持排队。引导请求成功后显示确认提示，时间线中的 `steeringUserMessage` 显示引导状态；任务恰好结束导致引导失败时，显示错误并保留失败消息。

队列显示排队、发送中或失败暂停状态。多条消息默认折叠为数量提示，点击可展开。点击尚未发送的消息进入文字编辑，右侧提供保存和取消；编辑期间保持展开且该消息不自动发送，保存保持队列位置和附件，取消放弃文字修改。删除直接移出队列。立即发送会请求打断当前任务，待会话空闲后优先发送选中消息；打断失败保留消息并标记失败。发送中或正在打断的消息不可编辑或删除。首条消息发送失败后暂停队列，用户可通过立即发送重试或删除该条消息，后续消息不会自动越过失败项。重试沿用消息的 `clientMessageId`。

点击停止同时暂停队列，暂停状态随标签页保存，刷新后仍保持暂停。主动暂停时立即发送按钮不可用；用户发送一条新消息且发送成功后，原队列才恢复并排在新消息之后。更新模型/权限或发送新消息失败时，原队列继续保持暂停。

本实现为当前标签页的客户端队列，使用 `sessionStorage`，不提供后台队列或跨设备同步。刷新保留队列；切换到其他会话时暂停，返回对应会话后恢复。关闭标签页会清除队列。只有对应会话已连接、接管开启、设备在线且具备发送能力时，才自动发送；错误状态下不自动续发。刷新前正在发送、结果未确认的消息恢复为失败暂停状态，不自动重复提交。

测试覆盖队列顺序、并发提交锁、取消、失败暂停/重试、刷新恢复、会话隔离，以及运行中的 Enter 发送、引导选择、只读限制、编辑保存/取消、立即发送优先级和打断失败。
