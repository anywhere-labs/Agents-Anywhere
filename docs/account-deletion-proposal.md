# 账号注销与数据删除设计

状态：**设计已确认，尚未实施**（2026-11-06）。本文描述目标设计，不是当前行为；实施时以源码为准，并同步更新 `docs/api/` 与本文。

关联：anywhere-labs/Agents-Anywhere#391、#130（用户询问删除云端数据与注销账号）、#550（管理端删除用户的修复）。

## 1. 背景与目标

当前用户只能通过删除设备来删除该设备同步到 Server 的会话、消息和附件，没有账号注销入口；管理端删除用户只删 `users` 一行：

- `connectors.user_id` 没有外键，设备会变成无主设备，设备凭据仍可连接；
- `sessions.project_id` 为 `RESTRICT`，用户项目下有会话时删除失败并返回 500。

#550 把管理端删除改为先逐台调用 `delete_connector_data` 再删用户，但仍是同步流程：中途失败返回 503，账号行无人收尾。

目标：

1. 用户可以在四端自助注销 Agents Anywhere 账号（所登录实例上的账号），管理员删除用户走同一流程。
2. 删除完整且一定完成：请求只做冻结，后台分步清除，任何一步中断都能续跑。
3. 冻结后立即切断所有访问路径，不留可被旧令牌、分享链接或配对码利用的窗口。
4. 删不掉或删不及时的部分（备份、日志、设备本地数据）在保留说明中写明。

范围外：Runtime 与模型服务商自身的账号；工作设备本地的 Agent 会话和项目文件；Tokens Anywhere 账号（接通后另行设计，见 §9）。

## 2. 已确认的决策

| 决策 | 结论 |
| --- | --- |
| 冷静期 | 不设。冻结后不可撤销；模型保留扩展位 |
| 本人确认 | 有密码的账号重新输入密码；否则使用发往已绑定邮箱的验证码，或重新完成 OAuth；界面另需输入邮箱或用户 ID 防误操作 |
| 用量统计 | 注销时删除该用户的 `usage_events` |
| 卡住阈值 | 同一步骤累计 24 小时仍失败，进入 `blocked`，交给管理员 |
| 保留周期数字 | **待定**：备份保留天数、日志保留天数、承诺完成删除的期限（见 §8） |

## 3. 领域模型

### 限界上下文

| 上下文 | 职责 |
| --- | --- |
| 账号生命周期（新增，属身份上下文） | 持有注销申请，编排整个流程 |
| 身份认证 | 签发本人确认凭证；拒绝冻结账号的所有登录方式 |
| 设备 | 单台设备的数据清除，复用 `services/connector_deletion.py` 的 `delete_connector_data` |
| 会话与内容、文件存储 | 由设备清除连带删除 |
| 用量统计 | 按用户删除用量事件 |
| 通知 | 受理与完成邮件 |
| Tokens Anywhere（外部） | 订阅「账号已注销」集成事件，经防腐层处理，AA 不直接操作 Tokens 数据 |

### 聚合根 `AccountDeletion`

每个用户最多一条，用户行删除后仍保留，作为删除凭据。

| 字段 | 说明 |
| --- | --- |
| `id` | 申请 ID |
| `user_id` | 随机用户 ID（`usr_…`），无外键 |
| `actor_kind` / `actor_user_id` | `self` 或 `admin`，以及管理员 ID |
| `authorization_method` | `password` / `email_code` / `oauth` / `admin` |
| `state` / `step` | 见状态机 |
| `attempts` / `next_attempt_at` / `last_error` / `failing_since` | 重试与卡住判定 |
| `claim_owner` / `claim_until` | 后台租约 |
| `notify_email` | 仅用于发送完成邮件，发送后置空 |
| `summary_json` | 删除的设备、会话、文件数量，不含个人信息 |
| `requested_at` / `completed_at` | 时间 |

值对象：`DeletionAuthorization`（本人确认凭证，5 分钟有效、只能使用一次、用途固定为 `account-deletion`）、`DeletionActor`、`DeletionSummary`。

### 不变量

- 存在未完成的注销申请时，用户必须为禁用状态，且不能被重新启用。
- 冻结后用户名下不能新增设备、配对、项目、分享和附件。
- 最后一个启用中的管理员不能被注销。
- 一个用户同时只有一条注销申请。

## 4. 状态机

```text
RequestAccountDeletion（单个事务）
        │
        ▼
     frozen ──▶ purging_devices ──▶ purging_residue ──▶ deleting_identity ──▶ completed
                     │                    │                    │
                     └──── 重试累计 24 小时失败或发现数据异常 ────┴──▶ blocked
```

- 所有转换规则放在 `core`，为纯函数。
- 每一步都可重入：重复执行结果不变。
- `blocked` 由管理员处理后回到当时的步骤继续。
- 不存在 `cancelled`：进入 `frozen` 后一定走到 `completed`。

## 5. 流程

### 5.1 本人确认

新增确认接口，按账号类型校验：

| 账号 | 方式 |
| --- | --- |
| 有密码 | 复用登录的密码校验（客户端沿用现有的盐与校验值流程） |
| 仅 OAuth，实例开启邮件且已绑定邮箱 | 邮箱验证码，新增用途 `account-deletion` |
| 仅 OAuth，无可用邮箱 | 重新完成一次 OAuth |

通过后签发 `DeletionAuthorization`。注销请求消费该凭证，重放无效。

### 5.2 `RequestAccountDeletion`（同步）

前置检查：用户存在且无未完成申请；本人确认凭证有效（自助）；不是最后一个启用中的管理员——检查时锁定管理员行，避免两个管理员并发注销后无人可用。

同一事务内：

1. 写入注销申请，状态 `frozen`。
2. 用户置为禁用。现有的密码、OAuth、扫码、手机刷新令牌登录都会拒绝禁用账号。
3. 名下全部设备标为待删（`revoked=2`），ingress 立即拒收。
4. 删除公开分享、扫码登录令牌、文件预览令牌、未使用的配对码。

提交后：发送「注销已受理」邮件；发布 Dashboard 变更，让在线客户端退出；唤醒 worker。

返回 `202`，带申请 ID 与状态。客户端收到后在本机退出登录并清缓存，不轮询。

### 5.3 `AccountDeletionWorker`（异步）

沿用 `services/goal/outbox.py` 的形态：按 `claim_until` 与 `skip_locked` 认领，指数退避，多 worker 与重启安全。

| 步骤 | 内容 |
| --- | --- |
| `purging_devices` | 每次重新列出剩余设备，逐台调用 `delete_connector_data`（断开连接、通知本地忘记目标、清时间线缓冲与运行态缓存、删数据库记录、删附件）；设备离线照常删除 |
| `purging_residue` | 按 `user_id` 删除邮箱验证码记录、用量事件和残留项目；发现用户项目里有其他用户设备上的会话时进入 `blocked`，不自行处理 |
| `deleting_identity` | 确认没有设备和项目后删除用户行，OAuth 绑定、头像随之级联删除；用户行不存在视为完成 |
| `completed` | 发送「注销已完成」邮件后清空 `notify_email`，写入删除摘要 |

### 5.4 入口

- 自助：`POST /api/v2/auth/me/deletion`，必须携带本人确认凭证。
- 管理端：`DELETE /api/v2/admin/users/{id}` 改为调用同一命令（`actor_kind=admin`），返回 `202`。
- 管理后台新增注销申请列表，显示进行中与 `blocked` 的申请及原因。
- `/auth/config` 声明注销能力与可用的确认方式；客户端据此显示入口，旧 Server 上不显示。

## 6. 安全

- **写接口检查账号状态。** 创建设备、认领配对码、创建项目、创建分享、上传附件当前只校验令牌签名（`current_user_id`），需改为查询账号状态（`current_user`）；否则冻结期间或删除后，未过期令牌仍能新建设备，留下无主设备。读接口维持现状：删除后只返回空数据，用户 ID 随机不复用。
- **分享链接在冻结事务内失效**，不等待后台清除。
- **并发**：冻结时设备即被拒收；删除与上传由设备生命周期锁串行化，进行中的附件上传先完成再删除。
- **错误码**：Server 对冻结或已删除账号返回 `account_deleting` / `account_deleted`，对已删除设备返回 `connector_deleted`，客户端与 Connector 据此给出明确提示。
- **审计**：注销申请永久保留，只含随机 ID、时间、发起人、确认方式与删除摘要；日志只记录随机 ID，不记录邮箱和昵称。

## 7. 离线与异常

| 场景 | 行为 |
| --- | --- |
| 工作设备离线 | 照常删除；上线后认证失败，Connector 停止并显示凭据失效。后续让 Connector 收到 `connector_deleted` 时清理本地与 Server 绑定的状态（凭据、目标与计划绑定），本地 Agent 会话不动 |
| 设备在线并在上传 | 冻结起拒收；进行中的附件先完成再删除 |
| 其他客户端离线 | 上线后收到 `account_deleted`，退出登录并清缓存（四端都需测试覆盖） |
| 请求中途断网或 Server 重启 | 冻结为单事务：要么未发生，要么已冻结并由 worker 续跑 |
| 存储或数据库暂时故障 | 退避重试；累计 24 小时失败进入 `blocked` 并告警 |
| 重复提交 | 申请按用户唯一，返回已有申请 |

## 8. 数据清单与保留说明

| 数据 | 处理 |
| --- | --- |
| 账号资料（邮箱、昵称、密码、头像、角色） | 删除 |
| OAuth 绑定、扫码登录令牌、文件预览令牌、配对码、邮箱验证码记录 | 删除 |
| 设备及其 Runtime 配置、模型目录、终端目录 | 删除 |
| 项目、会话、消息、目标、计划、分享链接、附件文件 | 删除 |
| Redis 中的时间线缓冲与运行态缓存 | 删除；其余为锁与序号计数器，不含内容 |
| 用量统计 | 删除 |
| 注销申请 | 保留，不含个人信息，作为删除凭据 |
| 数据库备份 | 按备份周期自然过期：**[待定] 天** |
| Server 日志 | 按日志保留周期过期：**[待定] 天** |
| 邮件服务商的发信记录 | 按服务商政策 |
| v1 迁移归档（`legacy_import_archive`） | 无用户字段，需先确认官方云是否有数据，再决定清理方式 |
| 工作设备本地数据、模型服务商数据 | 不在 Server 范围内，说明中写明 |

承诺完成删除的期限：**[待定]**。保留说明定稿后同步到四端隐私文案（`privacy.sections.retention`、`privacy.sections.contact` 及 iOS 对应条目）和 TokenHub 侧的官方隐私页。

各层按 [Server 架构](server-architecture.md)：

- `infra/repositories/account_deletions.py`：数据库实现；

| 阶段 | 内容 |

## 10. 验证

- **Server**：
  - 状态机单元测试；
  - 每一步重入测试；
  - worker 中断后续跑；
  - 两个 worker 并发认领；
  - 设备离线时注销；
  - 存储失败退避与 `blocked`；
  - 冻结后旧令牌调用写接口被拒；
  - 分享链接在冻结后立即 404；
  - 最后一个管理员并发注销；
  - 迁移的相邻升级与降级。
- **客户端**：四端各自的入口、确认、提交后退出，以及离线客户端上线后收到 `account_deleted` 的处理。
- **联调**：`./local-up.sh --with-connector` 下注册账号、配对设备、产生带附件的会话并创建分享，然后注销。核对数据库各表与附件目录已清空、设备被断开且无法重连、分享链接失效、登录被拒。
