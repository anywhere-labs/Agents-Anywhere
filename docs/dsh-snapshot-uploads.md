# DSH 大历史上传的 Connector 内存

Bridge 原来已在超过 8 MiB 时把页面写入 spool，但上传时仍将整个 spool 读回列表，再生成完整 JSON 字符串和 bytes，导致大历史重新占用多份内存。

现在提交时逐页读取，逐条编码到临时 JSON 文件，再以 64 KiB 块发送既有 `/connector/ingest` 请求。实例绑定、turn 字段过滤和完整快照的提交语义保持不变。认证重试从文件开头重读；成功、失败和取消都关闭临时文件。

这是 Connector 内部优化，没有新增 Server API、数据库表或分块续传协议。断开连接后仍会重传整个 HTTP 请求；已提交历史的位置仍由既有 checkpoint 保存。

自动化验证 512 条 Unicode 消息合成超过 32 MiB 的正文：逐条生成输入的编码与哈希阶段 Python 分配峰值低于 2 MiB。该测量不包含原生投影、Bridge 页缓存和 item ID 去重集合，也不是操作系统 RSS。

同规模约 32.2 MiB spool 的独立 Python 3.12 进程对比中，提交阶段 Python 分配峰值由约 75.5 MiB 降到 8.4 MiB，进程峰值 RSS 由约 151 MiB 降到 92.7 MiB。实际 Relay 仍会加载一页，包含最初最多 8 MiB 的缓存页。该合成样本不代表所有生产历史；Server 仍完整解析 JSON，不能据此宣称端到端内存有界。

## 分页上传

完整快照编码后不超过 45 MiB（`SNAPSHOT_PAGE_BYTES`，低于集群代理 50 MiB 的请求体上限）时，用一个 `/connector/ingest` 请求发出：`session.meta.upsert` 加 `timeline.sync {complete: true}`。Server 在一个事务里替换时间线，只改写有变化的条目，删除快照里已经没有的条目。2.1.0 的页大小是 8 MiB，8–45 MiB 的会话每次完整同步都要分页，第一页之后的历史会被整段删掉再写回；现在这些会话不再分页。

超过 45 MiB 时，Connector 按条目边界分页，每页是一个独立的请求体：第一页带 `session.meta.upsert` 并以 `complete: true` 整体替换时间线，之后各页以 `complete: false` 追加剩余条目。Server 不需要知道分页：条目按 `orderSeq` 升序到达，而 Server 对比已有最大值更大的新条目原样保留它的 `orderSeq`，所以逐页追加得到的时间线和单请求一样；被撤回的条目在第一页替换时就已清掉。

条目只编码一次，依次写进本地临时文件并记下位置，每一页是文件里连续的一段。页在发送时才切，所以中途换页大小不需要重新编码。

分页的"事务"不是原子的：第一页被接受到最后一页落库之间，Server 上该会话只有前面的部分，而且第一页之后的历史每次都会被删掉再写回。Connector 尽量缩短这个窗口：

- 各页连续发出。每一页（包括第一页）遇到瞬时失败（网络、5xx、408/429）都只重试当前页，最多 4 次，0.5 秒起翻倍退避。第一页一旦被接受就不再重发，因为它会删掉已追加的条目。
- 代理返回 413 时，按被拒那一页的实际大小减半重新切分，最低 1 MiB；这个上限说明的是部署本身，在本进程内一直沿用。超过 8 MiB 的页重试用尽时，如果是连接被断开（有的代理直接断开过大的请求而不返回 413），这一次上传改用 8 MiB；Server 停机、返回 5xx 或超时都不会让页变小。两种情况都从失败的那一页起重新切分剩余条目，第一页还没被接受就仍以第一页的身份重发。只有一个条目的页无法再切。
- Server 要解析并写完整页才回复，所以读超时随页大小延长，45 MiB 的页是 120 秒，避免慢库时把同一页整个重传。
- 重试用尽时抛出网络错误，走原来的重订阅路径重新捕获；无法再缩小的 413、其他 4xx 或 `rejected` 立即失败，按会话隔离。快照提交的返回（2.1.0 起为 `aa.dsh.v2.Sync.ingestSnapshot` 的返回值）与检查点仍只在最后一页被接受后才产生。

DSH 同步流开启检查点时，它的通知都已经同步落库，快照不需要排在 Connector 的共享上传队列之后，所以上传快照时不占用共享的上传锁，也不会让其他通知（例如同一设备上 Codex、Claude 的实时消息）改走 HTTP 队列排队。

代理的请求体上限最好不低于 50 MiB；更小也能工作，只是会多分页。要彻底去掉分页带来的整段重写和中途失败后的半截时间线，需要 Server 支持把多页当作一次快照提交，例如分页带 `captureId`、页序号和最后一页标记，在最后一页按整次快照的条目集合删除；这是跨端接口变化。
